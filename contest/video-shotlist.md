> `contest/기획안-공모전용.md` §6 대본(0:00~3:00)을 **컷 단위**로 쪼갠 문서다.
>
> - **내레이션 칸은 §6 문장을 그대로 나눠 담은 것이다.** 새로 쓰거나 줄이지 않았다. 읽는 순서도 §6 그대로다.
> - **자막 칸은 화면에 얹을 짧은 문구**다. 내레이션에서 그대로 따온 말만 썼다.
> - **화면 칸의 시연 시나리오는 `contest/submit-README.md` STEP 2 의 심사 동선과 같다.** 두 곳이 어긋나면 심사위원이 영상에서 본 것과 URL 에서 누르는 것이 달라진다.
> - 시간은 §6 의 구간 표기를 컷에 나눠 배분한 **목표값**이다. 낭독 속도에 따라 ±2초는 괜찮고, **총 3:00 을 넘기면 안 된다**(공모전 요건).

## ⚠ 촬영 전에 정할 것 하나 — 「보라색」을 어디로 넣을 것인가

§6 대본은 **「차분한 분위기와 보라색을 좋아하고」**라고 말한다. 그런데 실제 화면에서는 이 둘이 다르게 동작한다(`기획안-공모전용.md` 검증 기록 C-2).

| 촬영 방식 | 화면에서 벌어지는 일 | 대본과의 관계 |
|---|---|---|
| **A안 — 색 칩 `보라` 를 고르지 않는다.** 자유 서술 「바닷가의 보라색 노을」에만 보라를 담는다 | 3안이 `흰 튤립 / 과꽃 / **재스민**` → `흰 튤립 / 과꽃 / **글라디올러스**` 로 **눈에 보이게 바뀐다.** 「자유 서술이 결과에 반영된다」가 화면으로 증명된다 | 「보라색을 좋아하고」를 **자유 서술로 말한 것**으로 읽히게 해야 한다 |
| **B안 — 대본대로 색 칩 `보라` 를 고른다** | 자유 서술이 같은 말을 되풀이하게 되어 **3안이 바뀌지 않는다.** 단서 밴드만 추가로 뜬다 | 대본 문장 그대로지만, 1:36 컷의 「단서를 읽습니다」가 결과 변화로 뒷받침되지 않는다 |

**A안 확정(Advisor 판정 2026-08-19).** §8 체크리스트의 「자유 서술이 결과에 반영되는 시나리오가 있다」를 영상 안에서 만족시키는 유일한 방식이다. 아래 표의 화면 칸은 **A안 기준**으로 적었다. B안으로 갈 거라면 C08 의 「색 칩은 건드리지 않는다」만 바꾸면 된다.

또 하나. §6 은 「파도 소리를 좋아해요」를 AI 이해의 예로 든다. **정적 데모에서 이 문장은 단서를 하나도 만들지 않는다**(검증 기록 C-3). 이 문장을 **화면에 입력하는 컷으로 쓰지 말 것.** 말로만 스쳐 지나가거나, 본배포 화면으로 찍는다.

## 녹화 가이드

### 준비

- 녹화 **직전에** `contest/submit-README.md` STEP 1~3 을 끝내 둔다. **영상에 나오는 화면과 제출한 URL 이 같은 빌드여야 한다.**
- 브라우저는 **시크릿 창**으로 연다 — 북마크바·확장 프로그램·자동완성·로그인 상태가 찍히지 않는다.
- 주소창에 `[Netlify URL]` 을 띄운 채 찍는다(로컬 `localhost:3000` 이 찍히면 「실제 동작하는 URL」 인상이 깎인다).
- 브라우저 창을 **1920×1080 에 맞춰** 키우고, 확대 배율은 100% 또는 110%(작은 글씨 가독성을 위해 110% 권장).
- 알림·메신저를 전부 끈다. Windows 집중 지원(방해 금지)을 켠다.

### 화면 녹화

**Win+G (Xbox Game Bar)** — 설치가 필요 없는 쪽.

1. `Win+G` → 「캡처」 위젯 → 녹화 시작(`Win+Alt+R`).
2. 마이크는 위젯의 마이크 아이콘으로 켠다(**기본이 꺼짐이다 — 반드시 확인**).
3. 브라우저 창이 활성 상태여야 녹화된다. 창을 바꾸면 녹화가 끊긴다.
4. 저장 위치: `영상\캡처`.

**OBS Studio** — 슬라이드와 브라우저를 오가야 하므로 이쪽이 편하다.

- 설정 → 출력 → 녹화 품질 `고품질`, 형식 `mp4`, 인코더는 하드웨어(NVENC/QSV)가 있으면 그쪽.
- 설정 → 비디오 → 기본·출력 해상도 **1920×1080**, FPS **30**.
- 소스: 「디스플레이 캡처」 하나 + 「오디오 입력 캡처(마이크)」 하나.
- 장면을 둘로 나눠 두면(슬라이드 / 브라우저) C05·C13 의 전환이 깔끔하다.

### 음성

- 마이크는 입에서 **한 뼘** 거리. 노트북 내장 마이크도 조용한 방이면 충분하다.
- **한 컷씩 끊어 읽는다.** 실수하면 그 컷만 다시 읽는다 — 3분을 통으로 가려다 열 번 다시 찍게 된다.
- 각 컷 앞뒤로 **0.5초 정도 여백**을 남기면 편집에서 붙이기 쉽다.

### 편집 포인트

- **시연 구간(C07–C12) 배속 금지.** 실제 속도로 둔다. 배속을 걸면 「진짜 도는 것인지」 의심을 만들고, 이 영상의 목적이 바로 그 반대다. 실측상 이 동선은 원래 빠르다(결과 도착까지 20초 안팎).
- 대신 **기다림은 잘라낸다** — 페이지가 뜨는 사이의 빈 시간, 마우스가 목표까지 가는 시간은 컷 편집으로 지운다. 배속이 아니라 잘라내기로 줄인다.
- **클릭할 곳을 잠깐 멈춰서** 보여 준다. 마우스를 올린 채 0.5초 머문 뒤 누르면 시청자가 따라온다.
- **C09 의 단서 밴드**와 **C11 의 「WHY 이 꽃을 고른 이유」**는 확대(줌 인)해서 보여 준다. 이 영상에서 가장 중요한 두 장면이다.
- 자막은 **화면 아래 1/5 지점**에 고정하고, 검은 배경 위 흰 글씨라 그림자나 반투명 띠를 깐다.
- BGM 은 넣더라도 **내레이션 대비 아주 작게**(−25dB 정도). 저작권 자유 음원만 쓴다.
- 마지막 컷에서 `[Netlify URL]` 을 **읽을 수 있을 만큼 크게** 3초 이상 띄운다.

### 내보내기

- 1920×1080 / 30fps / mp4(H.264)
- **길이 3:00 이하** — 내보내기 뒤 실제 재생 길이를 다시 확인한다. 2:55 쯤을 목표로 잡으면 안전하다.
