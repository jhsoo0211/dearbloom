# dearbloom 디자인 시안 스펙 (3방향 × 3화면)

worker 3명이 각각 1방향(3개 HTML)을 독립 제작한다. §1 공통 스펙은 세 방향 모두 동일하게 준수하고, 목 데이터·카피는 §1.5 전문을 글자 그대로 사용한다(디자인만 다르고 콘텐츠는 동일해야 비교 가능).

---

## 1. 공통 스펙

### 1.1 산출물 파일 구조

```
design\
├── index.html                  ← 비교 페이지 (3방향 완료 후 Advisor가 제작)
├── a-botanical\  home.html / question.html / result.html
├── b-guide\      home.html / question.html / result.html
└── c-gallery\    home.html / question.html / result.html
```

- worker A → `a-botanical\` 3파일만, worker B → `b-guide\` 3파일만, worker C → `c-gallery\` 3파일만 생성. 다른 폴더는 절대 건드리지 않는다.
- 모든 파일: `<!DOCTYPE html>`, `<html lang="ko">`, `<meta charset="UTF-8">`, viewport 메타, `<title>dearbloom — {화면명} ({방향명})</title>`. UTF-8(BOM 없음) 저장.
- 화면 간 내비게이션(상대 경로): home CTA → `question.html`, question "다음" → `result.html`, 상단 로고 → `home.html`.

### 1.2 기술 규칙

| 항목 | 확정 | 이유 |
|---|---|---|
| CSS | `<style>` 인라인, 순수 CSS만. **Tailwind CDN 금지** | Tailwind Play CDN은 JS 런타임 — 오프라인이면 스타일 전멸 |
| CSS 변수 | `:root`에 §1.4 팔레트를 `--ivory --ink --stem --rose --lavender --gold`로 선언 후 사용 | hex 일탈 탐지 용이 |
| JS | 인라인 바닐라, 파일당 50줄 이내. 용도: 결과 3안 탭/전환, 멘트 3톤 탭, 복사 버튼(`navigator.clipboard.writeText` try/catch, 실패 시 무시) | 시연용 최소 |

- 자리: 챕터 01 리드 → 탄생화 각주 **아래**. 위계는 각주와 같은 단이다 — 이 줄은 읽는 것이 아니라 만지는 것이라, 리드보다 커지면 챕터의 주인공이 "오늘의 꽃"에서 색 고르기로 넘어간다
- 규격: §1.6b 칩(h44 · 선택은 `--cta-bg`/`--cta-fg` 짝 채움 **하나로만**). 머리말 `화면의 빛깔`은 11px 오버라인, 640px 아래에서는 칩 줄 위로 올린다
- **계열 색 점은 안 눌린 칩에만 있다** — 점은 그 계열이 어떤 색인지 보여 주는 **견본**이고(`숲빛`이 어떤 초록인지는 글자로 알 수 없다), 견본이 필요한 것은 아직 안 고른 쪽이다. 값은 팔레트 원색 고정(`--stem`/`--ivory-3`/`--gold`/`--rose`/`--lavender`) — 테마 변수를 쓰면 다섯 점이 전부 같은 색이 되어 견본 노릇을 못 한다. 점의 링은 `currentColor`: 고정 헤어라인(`--hair-2`)으로 두르니 계열색이 배경에 붙는 자리에서 점이 통째로 사라졌다(다크 위 숲 1.6:1 · 와인 2.49:1 — §1.6 비텍스트 하한 3:1 미달)
- **[2026-08-16 확정] 눌린 칩에는 점이 없다.** 한동안은 눌린 점을 `currentColor`로 넘겨 대비를 벌었다(원색 그대로는 채움색과 같아져 사라졌다 — 와인빛은 채움 `#8A3448`과 점 `--rose #8A3448`이 완전 일치, 금빛 1.7:1·보랏빛 2.3:1). 대비는 해결됐지만 그러면 눌린 칩이 **짝 채움 + 글자색 점** 두 가지로 선택을 말한다 — §1.6b의 "한 화면 한 선택 표현"이 금지하는 이중 표시다. 점을 지워도 잃는 것이 없다: 고른 순간 그 색은 화면 전체가 입고 있고, 견본은 남은 넷이 말해 준다
  - ⚠ 구현은 **가로 여백으로 폭을 되메운다**(`padding: 0 15px → 23.5px`, 479px 아래 `12px → 20.5px`). 점 10px + gap 7px = 17px이 빠지므로 좌우 8.5px씩을 얹어 칩의 상자를 그대로 유지한다 — 안 하면 칩을 누를 때마다 그 줄의 나머지 칩이 17px씩 밀린다
- 접근성: `role="group"` + `aria-labelledby`(머리말), 선택 상태는 `aria-pressed`, 전 항목 키보드 도달(네이티브 `<button>`). `aria-label`은 `{라벨} 색감으로 보기` — 보이는 텍스트로 시작하므로 WCAG 2.5.3 유지
- 진입 시 눌린 칩 = 오늘의 꽃 카테고리(v3.3의 "진입 시 1회 결정"은 그대로다 — 바뀐 것은 **사람이 바꾸는 방법**뿐)
- **[2026-08-16 확정] 고른 빛깔은 세션이 기억한다.** 예전에는 `useState`로만 들고 있어서 도감을 한 번 다녀오면 오늘의 꽃 카테고리로 되돌아갔다 — 사람이 고른 것이 말없이 되돌려지면 그건 선택이 아니라 장식이다. `sessionStorage` **1키**(`dearbloom.tint`, 값은 테마 slug)에 담고 게이트 세션 기억과 **같은 문법**(`useSyncExternalStore` + 서버 스냅샷 `null`)으로 읽는다 → 하이드레이션 경고 0, 뒤로 가기는 처음부터 실제 값. 저장값이 있으면 **무조건 이긴다**(선택 해제라는 개념이 없다 — "오늘의 꽃 따라가기"는 저장 전의 기본값이지 되돌아갈 상태가 아니다). 탭을 닫으면 잊는다
  - ⚠ 게이트와 달리 **부트 스크립트를 두지 않는다.** 빛깔은 `<html data-flower>`를 만져야 하는데 그 노드는 layout.tsx가 소유해 React 19가 속성 불일치를 그대로 잡아낸다(게이트가 `data-db-gate`로 겪은 그 실패). 테마는 지금도 마운트 뒤 이펙트가 입히므로 첫 프레임 기준은 달라지지 않는다
- 회귀 방어: 카테고리를 늘리면서 칩 목록을 잊으면 그 계열은 영영 고를 수 없는 색감이 된다. `tests/components/landing-today-reason.test.ts` §1.4c v3.4 블록이 칩 5개 ↔ `CATEGORY_THEMES` 전수 일치를 본다

#### 이야기 문체 규범 (2026-08-15 확정)

`content/stories.csv`는 **컬럼마다 다른 문체**를 쓴다. 섞이는 게 아니라 나뉘는 것이다.

| 컬럼 | 문체 | 비고 |
|---|---|---|
| `title` · `hook` | **합니다체 헤드라인 허용** | "양파인 줄 알고 먹었습니다" 류의 무덤덤한 신문 헤드라인 톤은 의도적 장치다. 이미 해요체인 제목·훅도 그대로 둔다(헤드라인은 양쪽 다 허용) |
| `story_ko` | **해요체로 일관** | `~습니다/합니다/입니다/됩니다` 종결 금지. 한 문단 안에서 해요체와 합니다체가 섞이는 것은 결함으로 본다 |

- **예외 — 본문 내 직접 인용**: 인용문은 화자가 다르므로 원 문체를 그대로 둔다. 따옴표가 없어도 앞 문장이 인용을 열고(“…지은 노래예요”) 인용 안에 다른 화자의 어투가 드러나면 인용으로 본다. 현재 해당 사례는 `story-hydrangea-manyoshu-eight-fold`의 『만엽집』 와카 번역문 1건.
- 문체를 바꿀 때 **사실·고유명사·수치·인용·문장 순서·분량은 건드리지 않는다.** 종결어미와 거기 딸린 최소한의 조사만 손댄다.
- 기계 치환은 금지. `~것입니다 → ~거예요`, `~바 있습니다 → ~적이 있어요`처럼 어색함이 남지 않게 문장 단위로 읽고 고친다.

**근거 1.** 헤드라인과 본문은 읽는 속도가 다르다. 제목의 합니다체는 한 줄을 툭 던져 놓는 무표정함이 매력이지만, 같은 어투가 본문 열 문장에 이어지면 안내문처럼 굳어 §1.5d가 세운 이야기·설화 톤을 깨뜨린다.
**근거 2.** 2026-08-15 워딩 전수 리뷰에서 본문 317편 중 311편에 합니다체가 섞여 있었고 279편은 **한 문단 안에서** 두 문체를 오갔다. 개별 문장이 아니라 문체 규범이 없다는 게 원인이라 판단해 컬럼 단위로 못박는다.

### 1.5n 오늘의 꽃 리드 — 세 마디 문단 (2026-08-16 사용자 요청 → 같은 날 재작성 → 2026-08-17 v3 전면 재작성 → v4 마디 ③ 재작성 → v5 전 벌 낭독 점검)

사용자 ①: "오늘의 꽃 추천 멘트를 감동적인 이야기나 **우리가 모은 이야기 기반으로** 감성적으로. 로컬에서도 작동."

뒷문장이 설계를 결정한다 — **모델을 부르지 않는다.** 재료(이야기 377편·꽃말·제철 근거)는 이미 카탈로그에 있으므로, 서버(`landing-build.ts`)에서 **규칙 조합**으로 짓는다. 그래서 키 없이도 돌고, 같은 날 새로고침은 같은 문장이 나온다.

**사용자 ② (같은 날 재작성 지시): "워딩이 너무 작위적이다. 진심을 담아 사람이 하는 것처럼."**

초판이 작위적이었던 원인은 문장 하나하나가 아니라 **틀이 한 벌뿐이라는 것**이었다. 진단 다섯:

| | 초판이 한 일 | 왜 기계처럼 읽히나 |
|---|---|---|
| ① | 매일 같은 뼈대에 값만 갈아 끼움 | 이 화면은 같은 사람이 며칠에 걸쳐 다시 온다 — **뼈대가 먼저 눈에 익는다** |
| ② | 독립 완결문 나열(사실 → 사실 → 안내) | 사람의 말은 문장끼리 이어진다 |
| ③ | 날짜를 두 번 부름(리드 `8월 16일` + 탄생화 `오늘 8월 16일`) | 같은 오늘을 두 번 통보한다 |
| ④ | `화면의 빛깔도…` `카드를 옆으로 넘기면…` | 시스템 설명조. 조작 안내는 캐러셀이 이미 한다 |
| ⑤ | 탄생화 줄을 기계적으로 병기 | 문단에 붙지 않고 표 한 줄이 떨어져 나온 모양 |

**답: 값이 아니라 틀을 회전시킨다.** 씨앗은 `날짜:슬롯` 문자열의 FNV-1a 해시뿐이라(`pickVariant`) **결정성은 그대로다** — 같은 날 새로고침은 같은 문단이고, 서버·테스트가 같은 값을 본다. 슬롯 이름을 씨앗에 섞는 이유는 표 길이가 같은 슬롯끼리 매일 같은 번호를 뽑지 않게 하기 위해서다.

**사용자 ③ (2026-08-17 재작성 지시): "아는 사람만 아는 내용 말하는 것 같잖아. 보다 친근하게 '오늘 날씨가 덥더라구요 그래서 시원한 수국을 골랐어요' 이런 느낌으로. 바로 이야기 넣지 말고."**

v2 는 두 마디였다 — `{꽃 이름 + 고른 이유}` 다음에 곧바로 `“{훅}” — {맺음}`. 걸린 것 둘:

| | v2 가 한 일 | 왜 거리감이 생기나 |
|---|---|---|
| ⑴ | 첫마디가 끝나자마자 설화 인용 | 꽃을 건네는 말이 아니라 **지식 카드**로 읽힌다. 처음 온 사람에게 설화부터 들이민다 |
| ⑵ | 맺음 한 벌이 `이 한 줄을 아는 사람이 많지 않더라고요.` | 아는 쪽과 모르는 쪽을 **가르고**, 우리를 아는 쪽에 세운다. 건네는 서비스가 할 말이 아니다 |

**답: 마디를 셋으로 늘리고, ③을 맨 뒤로 물린다.**

| 마디 | 하는 일 | 보기 |
|---|---|---|
| ① | **오늘이라는 날** | `8월 중순이잖아요.` |
| ② | **그래서 이 꽃을 골랐어요** | `이맘때는 눈이라도 시원한 게 반가워서, 마침 제철인 수국을 골랐어요.` |
| ③ | **(있으면) 이야기 한 줄** | `“…” — 저도 찾아보다 알게 된 이야기예요.` |

##### 지어낸 사실 0 — 날씨는 쓸 수 없다

사용자가 말한 결은 "오늘 덥더라구요"인데 **우리에게 기상 데이터가 없다.** 그 결을 흉내 내려다 날씨·기온을 지어내는 것이 이 개정의 유일한 사고 경로라, 재료를 처음부터 좁혔다.

- ①이 말할 수 있는 것은 **날짜에서 참으로 끌어낸 것뿐**이다 — 달, 순(旬: 1–10 초순 / 11–20 중순 / 21–말일 하순), 말일까지 남은 날
- ②는 **계절의 일반화**까지 허용한다(`여름에는 시원한 빛이 반갑잖아요`). 금지는 **오늘 하루의 관측을 단정하는 것**이다(`오늘 더웠어요` ✗)
- **24절기 이름은 부르지 않는다.** 절기는 해마다 하루 안팎 움직여 표 없이 못박으면 틀린 날이 생긴다. 달과 순만으로 같은 일을 할 수 있어 표를 들이지 않았다
- 금지 어휘(`날씨·기온·더위·추위·장마·비가·눈이 내·햇살…`)를 366일 전수로 막는다. **`눈`은 목록에 없다** — `눈이라도 시원한 게`·`눈이 갔어요`의 눈은 하늘이 아니라 우리 눈이다

#### 변주 표 (§1.5n v3)

**마디 ① — 오늘이라는 날.** 열한 벌이 순(旬)별로 갈린다. **계절 이름을 부르지 않는다** — ②가 부르는 자리라 둘 다 부르면 한 문단에서 같은 말을 두 번 한다.

| 순 | 조건 | 벌 |
|---|---|---|
| 초순 (1–10) | — | `{M}월 초예요.` / `달이 바뀌어 {M}월이에요.` / `이제 {M}월이네요.` |
| 초순 | ~5일 | + `{M}월이 막 시작됐어요.` |
| 중순 (11–20) | — | `{M}월 중순이잖아요.` / `벌써 {M}월 중순이네요.` / `{M}월도 절반쯤 왔어요.` |
| 하순 (21–말일) | — | `{M}월 끝자락이에요.` / `{M}월도 하순이네요.` |
| 하순 | 말일까지 1~6 | + `{M}월도 며칠 남지 않았어요.` |
| 하순 | 말일까지 ≤3 | + `곧 {M+1}월이에요.` |

- 날짜는 **문자열에서 쪼갠다**(`new Date(todayISO)`는 UTC로 파싱돼 서울 달력이 하루 밀린다). 읽을 수 없는 값이면 ①만 생략하고 ②(+③)로 선다
- **`며칠 남지 않았어요`는 말일 당일에 서지 않는다** — 남은 날이 0인데 "며칠 남았다"고 하면 그날 하루가 틀린 말이 된다. 그날은 `곧 {M+1}월이에요`가 받는다
- **중순은 세 벌뿐이다.** 넷째 자리를 채우지 않은 것이 의도다 — 아래 §1.5n v5 참조

**마디 ② — 날과 꽃을 실제 속성으로 잇는다.** 재료는 카탈로그가 가진 것뿐이다: 대표색(`colors[0]`) · 향(`fragrance_level`) · 결(`aesthetic_tags`) · 개화 폭(`bloom_months`) · 제철 근거(`basis`). **꽃말은 쓰지 않는다** — ③의 폴백 재료라 겹치면 훅 없는 날 한 문단이 같은 재료를 두 번 말한다.

색 → 인상 매핑(`COLOR_TONES`)은 **사실 주장이 아니라 우리 눈의 인상**이라 단정형을 쓰지 않는다(`시원합니다` ✗ / `시원해 보여서` ✓).

| 인상 | 색 | 그 인상을 반기는 계절(`SEASON_WELCOME`) |
|---|---|---|
| cool | blue `시원한` · green `서늘한` · white `맑은` | 여름 |
| warm | red · orange · coral `따뜻한` | 가을 · 겨울 |
| bright | yellow `환한` | 봄 · 겨울 |
| soft | pink `부드러운` · cream `포근한` | 봄 |
| deep | purple `차분한` · magenta `짙은` · brown `깊은` | 가을 |

`variegated`는 일부러 비워 뒀다 — 무늬가 섞인 색에서 한 갈래의 인상을 뽑는 것 자체가 무리다(대표색이 그것인 꽃도 없다).

| # | 조건 | `in_season` 벌 |
|---|---|---|
| 0 | 색 인상 ∈ 계절이 반기는 결 | `이맘때는 {반가운 말}, 마침 제철인 {꽃}을 골랐어요.` |
| 1 | 〃 | `{계절}에는 {인상} 빛이 반갑잖아요. 지금 한창인 {꽃}을 꺼냈어요.` |
| 2 | 〃 | `{계절}이라 {인상} 쪽으로 손이 갔어요. 마침 제철인 {꽃}이에요.` |
| 3 | 색은 있으나 **공명 아님** | `빛깔이 {인상}해 보여서 눈이 갔어요. 마침 제철이라 {꽃}을 꺼냈어요.` |
| 4 | 향 3 | `향이 진해서 한 송이만 둬도 티가 나요. 지금이 제철이라 {꽃}을 꺼냈어요.` |
| 5 | 향 0 | `향이 거의 없어 어디에 둬도 편해요. 지금이 제철이라 {꽃}을 골랐어요.` |
| 6 | 결 있음 | `{결 한 마디} 눈이 갔어요. 마침 제철이라 {꽃}을 꺼냈어요.` |
| 7 | 개화 1–2달 | `일 년에 두 달만 피는 꽃이거든요. 지금이 그 안이라 {꽃}을 꺼냈어요.` |
| 8 | 개화 12달 | `일 년 내내 볼 수 있는 꽃이지만, 오늘은 {꽃}이 먼저 떠올랐어요.` |
| 9 | ①이 섰을 때 | `그래서 지금 피어 있는 꽃들 사이에서 {꽃}을 꺼냈어요.` |

- **3번은 0~2번과 상호배타다.** `여름에는 시원한 빛이 반갑잖아요`와 `빛깔이 시원해 보여서`는 같은 말을 세기만 달리한 것이라, 같은 후보군에 두면 사용자가 짚어 준 문장(계절↔색)이 절반 이하로 밀린다
- 결 한 마디(`TAG_PHRASE`): calm `요란하지 않은 꽃이라` / minimal `군더더기 없이 생긴 꽃이라` / elegant `선이 단정한 꽃이라` / cute `보고 있으면 마음이 조금 풀리는 꽃이라` / vivid `색이 또렷한 꽃이라`. **모양을 단정하는 말(`동글동글한`)은 피한다** — 같은 태그 아래 생김새가 제각각이다
- `adjacent`·`all`은 세 벌씩만 둔다(색 / 결 / 날). **현 카탈로그는 366일 전부 `in_season`**이라 화면에 뜨지 않는 사다리다
- **무조건 서는 벌은 표 밖(`WHY_FALLBACKS`)에 둔다.** 표 안에 두면 매일 후보군에 섞여 재료를 쥔 문장들을 5분의 1씩 밀어낸다 — 실측으로 확인하고 뺐다

**마디 ③ — 재료 3단.** 훅이 있으면 **꽃말은 부르지 않는다**(한 문장에 재료 둘을 겹치면 인용이 묻힌다).

| 재료 | 벌 |
|---|---|
| ① 이야기 훅 | **㉠㉡㉢ 세 조각** — 아래 §1.5n v4 |
| ② 꽃말만 | `‘{꽃말}’이라는/라는 말을 품고 있어요. 오늘 같은 날 꺼내기 좋은 말이라서요.` / `품고 있는 말은 ‘{꽃말}’이에요/예요. 그 말이 오늘 먼저 떠올랐어요.` / `‘{꽃말}’이라는/라는 말을 오래 들어 온 꽃이에요.` |
| ③ 둘 다 없음 | **마디를 세우지 않는다.** ①+②만으로 완결된 문단이다 |

- v2에 있던 빈손용 세 벌(`이야기는 아직 모으는 중이에요…`)은 **뺐다.** 세 마디로 늘어난 지금 ①+②만으로 문단이 서고, 없는 것을 굳이 말하면 그 자체가 안내문 어조다
- 꽃말 뒤 조사는 받침이 가른다(`hasFinalConsonant`) — `‘맑은 마음’이라는` / `‘인내’라는`

#### §1.5n v4 — 마디 ③ 을 세 조각으로 (2026-08-17 사용자 피드백 두 번째)

**사용자 ④: "이야기도 감성적으로 적자. 갑자기 이야기 한 줄 나오고 «멈추게 되는 문장이었어요» 하니까 뭔 말인지 모를 수도 있으니까."**

v3 의 ③ 은 `“{훅}” — {맺음}` 두 조각이었다. 진단:

| | v3 가 한 일 | 왜 거리감이 생기나 |
|---|---|---|
| ⑴ | 인용을 홀로 세움 | **훅은 이야기 본문 위에 얹히도록 쓰인 헤드라인**이다. 본문에서 떼어 내면 단서가 없다 — `“물을 많이 먹어서 붙은 이름이 아니었습니다”`만 보면 무엇의 이름인지, 그럼 어디서 왔는지 알 길이 없어 **수수께끼**가 된다 |
| ⑵ | `읽다가 한참을 멈추게 되는 문장이었어요` | 독자는 아직 이야기를 읽지 않아 그 감정을 가질 수가 없다. **멈출 이유를 못 찾은 채 멈추라는 말만** 듣는다 — 우리만 아는 감동을 통보하는 꼴이라, v2 의 "아는 사람만 아는" 문제가 형태를 바꿔 되살아났다 |

**답: ③ 을 ㉠ 좌표 → ㉡ 인용 → ㉢ 초대 로 나눈다.**

**㉠ 어디서 온 이야기인지.** 재료는 그 이야기 행이 실제로 가진 것뿐: `culture_region` · `era` · `story_type` · `confidence_level`. **내용을 요약하지 않는다** — 우리가 본문을 다시 쓰는 순간 사실이 틀어진다. ㉠ 은 출처의 좌표만 말한다.

| # | 조건 | 벌 |
|---|---|---|
| 0 | 지역+시대(시대가 지역을 품지 않을 때) | `{시대} {지역}에서 온 이야기예요.` |
| 1 | 지역+갈래 | `{지역}에서 오래 전해 오는 / {지역} 쪽 기록에서 온 / {지역} 문학에서 온 이야기예요.` |
| 2 | 지역 | `{지역}에서 전해지는 이야기예요.` |
| 3 | 시대(지역 없음, 또는 시대가 지역을 품음) | `{시대}에 있었던 이야기예요.` |
| 4·5 | 갈래(**지역 없을 때만**) | folklore `오래 전해 오는 이야기가 하나 있어요.` / `입에서 입으로 전해 온 이야기예요.` · history `기록에 남아 있는 이야기예요.` / `기록으로 남은 이야기 하나를 옮겨 볼게요.` · literary `문학에서 온 이야기예요.` / `글 속에 남은 이야기예요.` |
| 6 | single_source | `드물게 전해지는 이야기예요.` |
| 7 | varies | `전하는 데마다 조금씩 다른 이야기인데요.` |
| — | **story_type = original** | `dearbloom이 지어 본 이야기예요.` — **회전 밖**에서 가로챈다 |

- **지명은 표(`REGION_LABEL`)를 통과한 값만 부른다.** 438편이 120가지 넘는 `culture_region`을 쓰는데, `western`·`global`·`europe`·`near-east`처럼 지명이 아니라 범주인 값과 `japan-bermuda-usa`·`persia-bulgaria`처럼 여러 곳을 이어 붙인 값이 섞여 있다. `서양에서 온 이야기예요`는 아무 좌표도 주지 못하고 `일본·버뮤다·미국에서 온 이야기예요`는 문장이 아니다 — **표에 없으면 지명을 부르지 않고** 시대·갈래로만 잡거나 ㉠ 을 통째로 생략한다(366일 중 27일). 시대(`ERA_LABEL`)도 같은 규율이라 `modern`(130편)·합성 값은 뺐다
- **시대가 지역을 품은 값**(`조선 시대`·`에도 시대`·`빅토리아 시대`)은 0번에 서지 못한다 — `조선 시대 한국에서 온 이야기예요`는 같은 말을 두 번 한다
- **갈래만 쓰는 벌은 지역이 없을 때만 선다.** 지역이 있는 날에도 후보로 두니 좌표를 두 칸 쥐고도 `기록에 남아 있는 이야기예요.` 한 마디로 여는 날이 122일까지 올라갔다(실측) — ②에서 색인상을 공명 날에 물린 것과 같은 판단
- **`original`은 회전 대상이 아니다.** §1.5f 가 건 창작 라벨이 다른 벌에 밀려 사라지면 안 된다

**㉡ 훅 인용.** 규칙 그대로(아래 인용 규칙). 원문은 손대지 않는다.

**㉢ 맺음 — 감정 통보에서 초대로.** 네 벌 전부 v4에서 다시 썼다.

| # | 문장 |
|---|---|
| 0 | 이어지는 대목은 도감에 적어 두었어요. |
| 1 | 앞뒤 사연은 도감에 다 있어요. |
| 2 | 무슨 이야기인지는 도감에서 마저 읽어 보실 수 있어요. |
| 3 | 나머지는 도감에서 천천히 읽어 보셔도 좋아요. |

- **㉠과 같은 낱말을 쓰지 않는다.** ㉠은 거의 모든 벌이 `…이야기예요.`로 끝나고 한 벌은 `…옮겨 볼게요.`다. ㉢까지 `이어지는 이야기는 도감에 옮겨 두었어요.`라고 하면 한 문단에서 `이야기` 세 번, `옮기다` 두 번이 된다 — 그래서 넷 중 셋은 다른 낱말(`대목`·`사연`·생략)로 같은 말을 한다

- **이 안내가 참인 근거:** 오늘의 꽃 카드는 덮개 링크로 `/flowers/{id}`로 가고(`TodayCarousel` — 카드에 `도감에서 보기` 라벨이 보인다), 그 상세의 `꽃에 얽힌 이야기` 구획이 그 꽃의 이야기를 **전문 그대로** 싣는다. **그 동선을 걷어 내면 네 문장이 거짓이 되므로 함께 고쳐야 한다** — 테스트가 카드 마크업의 `href`를 직접 읽어 지킨다
- **인용은 늘 ㉢ 앞에 서고 ㉢ 이 회전한다.** 순서를 뒤집어 인용으로 문단을 끝내면, 마침표 없이 끝나는 훅 105편에서 문단이 잘린 것처럼 보인다

#### §1.5n v5 — 변주 칸을 채우려고 문장을 지어내지 않는다 (2026-08-17 사용자 피드백 세 번째)

**사용자 ⑤: "`8월의 가운데 열흘이에요` 이게 뭔 말이니."**

중순(中旬)을 글자 그대로 푼 말이다. **뜻으로는 맞지만 아무도 그렇게 말하지 않는다.** 그 문장이 왜 태어났는지는 v3 계측 보고에 그대로 적혀 있다 — *"날짜만으로 중순에 대해 참으로 할 수 있는 말이 많지 않아 **표현 변주로 채웠다**."*

**규칙: 벌 수는 목표가 아니다.** 자연스러운 말이 셋뿐이면 셋으로 간다. 네 번째 자리를 억지로 채운 어색한 문장 하나가 늘어난 변주의 이득을 통째로 까먹는다 — 사용자는 그 하나를 보고 서비스 전체를 의심한다. 새 벌을 넣기 전에 **소리 내어 읽고** 물어라: "사람이 말할 때 이렇게 말하나?" 애매하면 넣지 마라. 버려서 그 갈래에 한 벌만 남아도 된다.

이 개정에서 **전 벌을 소리 내어 읽고** 아홉 문장을 버리거나 고쳐 썼다.

| 버린 말 | 왜 |
|---|---|
| `{M}월의 가운데 열흘이에요` | 중순의 직역. 사용자가 짚은 그 문장 |
| `{M}월 한가운데예요` | 문어투 |
| `{M}월의 첫머리예요` | `첫머리`는 글에 쓰는 말이지 달에 쓰지 않는다 |
| `{M}월이 저물어 가요` | `저물다`는 하루·한 해에 쓴다 |
| `{M}월에서 {M+1}월로 넘어가는 참이에요` | 설명조 → `곧 {M+1}월이에요` |
| `이제 막 {M}월에 들어섰어요` | 문어투 → `{M}월이 막 시작됐어요` |
| `{M}월도 하순으로 접어들었어요` | 일기예보 말투 → `{M}월도 하순이네요` |
| `제철은 한 뼘 비켜 있지만요` · `제철과 한 뼘 떨어진 날이라` | 문어투 → `제철에서 조금 비켜…` |
| `순서를 미루지 않고` | 무슨 순서인지 짚이지 않는다 — 우리 머릿속 로테이션의 말 |
| `지금이 그 안이라` | "그 안"을 되짚게 만든다 → `지금이 딱 그 두 달이라` |

`tests/components/landing-today-reason.test.ts`의 `UNSPOKEN_PHRASES`가 366일 전수로 되살아나지 못하게 막는다. **회전 테스트의 기대 수를 올려서 통과시키지 마라** — 숫자를 늘리려면 자연스러운 말을 먼저 찾아야 한다.

**요일·날짜 축은 들이지 않았다(검토 후 기각).** 두 가지 이유다.
- **신선도**: `revalidate = 3600`이라 자정 직후 최대 한 시간은 어제 페이지가 서고, 정적 데모(`npm run build:static`)의 `out/`은 빌드 시점에 아예 얼어붙는다. 달·순은 하루 이틀 어긋나도 대개 맞지만 **틀린 요일은 읽는 사람이 즉시 안다**
- **①의 일**: ①은 ②를 여는 자리다. `8월 중순이잖아요. 이맘때는…`은 `이맘때`가 ①을 받지만, `주말이네요. 이맘때는…`은 받을 것이 없어 ①이 장식으로 떨어진다. 날짜 그대로(`8월 17일이에요`)는 §1.5n이 v2에서 없앤 **날짜 두 번 통보**(히어로 캡션 + 탄생화 줄)로 되돌아간다

**이름이 색을 말하면 그 색을 믿는다.** 대표색(`colors[0]`)은 종(種)의 색이고 화면 이름은 테마가 고른 품종의 이름이다. `lily-asiatic`은 `colors[0]`이 `orange`인데 화면에는 `흰 백합`으로 서서 `빛깔이 따뜻해 보여서 흰 백합을 꺼냈어요`가 나왔다 — **읽는 사람 눈에 곧장 걸리는 모순**이라 `NAME_COLOR`(흰·하얀·빨간·붉은·노란·파란·보라·분홍)가 이름을 우선한다. 이름에 색말이 없으면 그냥 `colors[0]`이다.

### 1.5o 콘텐츠 크로스 링크 1차 (2026-08-18 사용자 요청)

> "꽃말이나 스토리 등등 연결시켜서 링크 보여줘도 좋을 것 같아."

원칙 하나로 정리한다. **꽃말과 이야기가 등장하는 자리에서 그 근원으로 갈 수 있어야 한다.** 화면이 어떤 이야기를 꺼내 놓고 "나머지는 저기 있어요"라고 말하면서 갈 문을 두지 않으면, 그 말은 안내가 아니라 통보다. 전부 내부 링크라 **정적 드롭(`output: 'export'`)에서도 그대로 돈다** — 이 조건이 설계를 가른다(아래 ①).

| 자리 | 무엇이 길이 되나 | 어디로 |
| --- | --- | --- |
| ① 이야기 아카이브 | 주소 자체 — `/stories?story={storyId}` | 그 이야기 시트가 **열린 채로** 선다 |
| ② 랜딩 오늘의 꽃 리드 | 맺음 문장 ㉢(`HOOK_CLOSINGS` 네 벌) | 그 꽃의 도감 상세 `/flowers/{id}` |
| ~~③ 탄생화 사전 시트~~ | ~~`도감에서 이 꽃 더 보기 →`~~ | **넣었다가 걷어냈다** — 아래 ③ |

**① 딥링크가 지키는 선.**
- **서버에서 `searchParams`를 읽지 않는다.** 읽는 순간 `/stories`가 요청 시점 렌더가 되고 정적 데모 빌드가 깨진다(`/r`이 같은 이유로 `location.search`를 읽는다). 클라이언트가 `useSyncExternalStore`로 읽되 **서버 스냅숏은 `null`** 이다 — `''`(질의 없는 주소)와 "아직 못 읽었다"를 구별해야 주소 동기화 이펙트가 딥링크 값을 읽기 전에 지우지 않는다
- **읽는 것은 첫 진입 한 번뿐이다.** 계속 파생 상태로 두면 시트를 닫는 순간 주소가 그것을 다시 연다
- **id는 남이 적는 값이다.** 생김새(`^[a-z0-9][a-z0-9-]{0,79}$`)로 한 번, 서버가 내려보낸 목록과 맞춰 한 번 — 두 문을 다 지나야 열린다. 어긋나면 **조용히 목록만** 선다(사과문을 세우지 않는다)
- **`replaceState`다.** 여닫기를 히스토리에 쌓으면 뒤로 가기가 "이 화면을 떠나는 길"이 아니라 방금 본 이야기들을 거꾸로 되짚는 계단이 된다 — 아카이브는 원래 이것저것 눌러 보는 화면이라 그 계단이 가장 길어진다
- **성능 경계를 건드리지 않는다.** 레인 지연 렌더와 전문 지연 로드는 그대로다. 시트가 여는 목록(`flat`)은 부모가 통째로 들고 있어 아직 카드를 세우지 않은 줄의 이야기도 그대로 열리고, 전문은 그때 한 편만 온다

**② 맺음이 곧 길.** 맺음 네 벌은 전부 "나머지는 도감에 있어요"라는 **초대**인데 여태 갈 곳 없는 글자였다. 카드 전체가 이미 같은 곳으로 가지만, 초대에 응하는 가장 짧은 길이 그 문장 위여야 한다.
- **문구를 바꾸지 않는다.** 서버가 `lead`/`text` 조각으로 내려보내고(`todayReasonLink`), 이으면 `todayReason`과 글자 하나까지 같다(탄생화 각주의 `lead`/`tail`과 같은 수법 — 문장 한 마디만 링크일 때 문자열 하나로는 못 낸다)
- 맺음이 서지 않는 날(훅이 없어 ③이 꽃말·침묵으로 물러난 날)은 **키 자체가 없다.** 없는 길을 만들지 않는다
- 조판은 본문 링크다 — 밑줄 + 한 단 진한 글자뿐. 버튼으로 세우면 리드 끝에 CTA가 붙은 모양이 되어 §1.5e 절제와 어긋나고 바로 아래 주 CTA와 위계를 다툰다

**③ 사전 시트의 다리 — 만들었다가 걷어냈다 (2026-08-18 Advisor 결정).** 애초 의도는 이랬다: 시트가 보여 주지 **않는** 것(색깔별 꽃말·반려동물 안전성)이 도감 상세에 있으니 `entry.link`가 있는 86일에 하단 한 줄을 붙인다.

구현 뒤 검증에서 **그 줄이 뜰 자리가 없다는 것이 드러났다.** 사전 목록 줄은 이어지는 날이면 `<Link>`로 도감에 곧장 가고, 나머지만 `<button>`으로 시트를 연다(`BirthDictionary`의 `DictRow`). 즉 **시트는 도감에 없는 날에만 열린다** — 다리는 영원히 렌더되지 않는 코드였다. 1월 실측: 31줄 중 도감 티어 11줄은 전부 링크.

그래서 되돌렸다. 판단의 근거는 셋이다.
- **현 배선이 더 나은 UX다.** 도감에 있는 꽃을 시트로 한 번 거쳐 가게 하는 것보다 목록에서 곧장 가는 편이 짧다
- **그 갈림의 접근성 근거가 유효하다.** 낭독기에서 "링크"와 "버튼"이 갈려 들려야 어디로 가는지 안다. 겉모습만 같게 두고 동작만 바꾸면 둘이 구별되지 않는다
- **죽은 코드는 다음 사람의 시간을 먹는다.** 렌더될 수 없는 다리를 남겨 두면 "왜 안 뜨지"를 누군가 처음부터 다시 조사한다

⚠ **배선을 바꿀 생각이라면 티어 고지도 함께 봐야 한다.** 시트가 이어진 날에도 열리게 되는 순간, 바로 위 `BIRTH_DICT_TIER`(`아직 도감에 들이지 못한 꽃이에요`)가 **도감에 있는 꽃 옆에서 거짓말이 된다.** 다리와 티어 고지는 한 짝이다 — 하나만 손대지 마라. 그때도 원칙은 그대로다: 이어지지 않는 280일에는 아무것도 붙이지 않는다(그 자리를 검색이나 목록으로 가는 대체 링크로 메우면 없는 상세를 있는 것처럼 가리키는 일이고, 2단 티어가 가장 경계하는 자리다).

**다음 라운드(미착수).** 결과 화면(`components/flow/**`)과 도감 상세의 이야기 카드에서 `/stories?story=…`로 나가는 길, 꽃말 → 그 꽃말이 붙은 다른 꽃으로 가는 길.

### 1.5f 이야기 수집 원칙 (2026-08-14 사용자 7차 확정)

- **문화권 무제한**: 서양·동양 가리지 않는다 — 그리스·로마, 오스만·페르시아, 중국·일본·한국, 이집트, 북유럽, 켈트 등 다양성 자체가 가치. 같은 꽃의 문화권별 상반 해석은 적극 수집
- **재미 우선**: 도파민·로맨틱·비극·유쾌 — confidence 라벨("드물게 전해지는 이야기예요")만 정직하면 출처 약한 설화도 수집 대상
- **픽션 허용**: `story_type` 구분을 도입한다 — `folklore(설화·전승) | history(역사) | literary(문학 유래) | original(dearbloom 창작)`. **original은 화면에 "dearbloom이 지어 본 이야기예요" 라벨 필수**(창작을 사실처럼 보이게 하지 않는 것이 유일한 금지선). 창작 이야기는 source_url 면제, 나머지는 출처 필수
- 실존 인물·실존 브랜드를 소재로 한 창작 금지(명예·권리). 신화 인물·역사 인물의 기록된 일화는 가능
- 적용: stories 스키마에 `story_type` 컬럼(차기 데이터 적재 작업에서 추가), 화면 라벨은 §1.5d 이야기 톤

### 1.5g 사진 위 꽃 이름 가독성 규칙 (2026-08-15 사용자 피드백 — "글씨는 보이되 감성은 살려라")

꽃 이름·꽃말이 사진 위에서 잘 안 보인다는 피드백. 전면 오버레이로 사진을 죽이지 말고 **국소 처리**로 해결한다:
- **국소 스크림**: 텍스트 블록 뒤에만 radial/linear 그라디언트 밴드(가장자리 페더 24px+) — 사진 전체 밝기는 유지
- **타이포 보강**: 꽃 이름은 마루 부리 400 이상(300 금지) + `text-shadow: 0 1px 24px rgba(base, .55)` 계열 소프트 섀도 허용(하드 아웃라인 금지)
- **배치 우선**: 가능하면 사진의 어두운 영역 위에 텍스트를 얹는 구도를 먼저 선택(이미지별 초점 좌표를 theme 상수에 기록 가능)
- **검증**: 사진 위 텍스트는 항상 픽셀 실측 4.5:1(기존 문화 유지) — 스크림·섀도 적용 후 기준
- 적용 대상: 랜딩 히어로·오늘의 꽃, 앱 홈 히어로 카드, 그룹 부케 카드 등 사진 위 모든 세리프 텍스트

**호버 강화 상태 (2026-08-15 사용자 10차 — "커서를 가져가면 잘 보이게")**
- 기본 상태는 위 규칙대로 **항상 읽히는 상태**(4.5:1) — 호버로만 보이는 텍스트 금지(모바일에 호버 없음, §1.6 앤티패턴)
- `:hover`/`:focus-visible`/터치 시 **강화 상태**: 국소 스크림 심도 증가(예: .35→.65) + 꽃 이름 밝기·크기 소폭 상승(scale ≤1.03) + 꽃말·설화 티저 1줄 추가 노출. 전환 200~300ms, reduced-motion 시 즉시
- 터치 기기: 첫 탭 = 강화 상태 토글(두 번째 탭이 링크 이동이 되지 않게 카드 전체 링크와 분리), 슬라이드 스와이프와 제스처 충돌 금지

### 1.5i 결과 화면 위계 확정 + 꽃말 조합기 로드맵 (2026-08-15 사용자 12차)

**결과 화면 정보 위계 (위 → 아래)**:
1. **꽃 (3D/사진) + 꽃 이름 + 꽃말** — 주인공, 최대 크기
2. **꽃에 얽힌 설화** — featured 전체 노출 + "다른 이야기 보기"가 **한 번의 탭으로** 열림(썰·추가 스토리 탐색이 핵심 경험). 나라별 꽃말도 이 블록에 인접
   - **이야기 상세보기 (2026-08-15 사용자 14차)**: 모든 이야기(featured·others)는 누르면 **상세 뷰(바텀 시트/전면 카드)**가 열린다 — hook(티저) → 전문(story_ko) → 문화권·시대 라벨 → story_type 라벨(original이면 "dearbloom이 지어 본 이야기예요") → "이야기의 갈래 —" 출처 각주. others 목록은 hook 1줄+mood 칩으로 표시하고 탭하면 같은 상세 뷰. 뒤로 닫기·스크롤 잠금·aria-modal·포커스 트랩, reduced-motion 시 즉시 표시
   - **여러 이야기 탐색 (2026-08-15 사용자 15차)**: 한 개가 아니라 **그 꽃의 이야기 전부**를 볼 수 있게 — "다른 이야기 보기" 확장 시 `pickStories`를 k=전체로 호출(제한 없음, mood 다양성 정렬 유지). 목록 상단에 **mood 필터 칩**(전체·romantic·tragic·funny·mythic·dramatic·healing — 한국어 라벨: 로맨틱·비극·유쾌·신화·드라마·위로)으로 골라 볼 수 있게. 상세 뷰 안에서 이전/다음 이야기로 넘기는 내비게이션 제공(스와이프 또는 버튼)
3. 추천 이유 · "이런 날 건네보세요" 상황 예시
   - **이야기 내부 위계 (2026-08-15 사용자 16차)**: 카드·상세 시트 모두 **hook·본문(이야기 자체)이 먼저** — 문화권("케냐" 등)·시대·갈래·신뢰 라벨 메타는 본문 **아래** 각주 줄로 후치. 카드 상단에 지역·시대 칩 금지(꽃 이름·mood 칩만 상단 허용)
4. 멘트 3톤 + 함께 담을 한 줄
5. **최하단 참고 블록(작게)**: 반려동물 배지(§1.5h) · 계절 · **가격은 "3~4만 원대" 언급 1줄만**(표·강조 금지) · 제휴 링크·고지
- 원칙: "정보"보다 "이야기"가 먼저. 안전·가격·구매는 필요할 때 찾을 수 있는 위치면 충분

**꽃말 조합기 (로드맵 등재 — 원문 리서치 §6.2, 지금 구현하지 않음)**:

### 1.5j 에피소드·상대방 서술 입력 (2026-08-15 사용자 13차 — "스토리·감성·생각해주는 마음")

**플로우 3단계(상대는 어떤 분인가요) 확장 — 자유 입력 2필드(모두 선택 사항)**:

- `함께한 기억이나 에피소드가 있나요?` — 자유 서술 (예: "작년 봄에 같이 튤립 축제에 갔어요")
- 마이크로카피: "적어주신 이야기는 추천과 멘트에만 쓰고, 저장하지 않아요."

**활용 (LLM 미연동 단계 — 휴리스틱)**:
- 엔진: `inferCuesFromText(text)` — 키워드 매핑(조용·차분→calm, 화려→vivid, 색 이름→colorPrefs, 꽃 이름→해당 꽃 가점)으로 `recipientTraits`·`colorPrefs`·`personalCues` 보강

**[2026-08-18 개정] P 점수 실동작 — 에피소드가 순위를 움직인다**

감사 P1-1 이 잡은 대로 `score.ts` 의 `P` 는 `const P = 0` 스텁이었고 `D` 는 합산식에 아예 없어서, `weightsSchema` 가 합 1.0 을 강제하는데도 fitScore 의 실제 상한은 0.85 였다. 항을 빼서 맞추지 않고 **식을 채워서** 맞췄다.

- **P(0.10) — 개인화**: `personalCues`(수신자 메모·에피소드 원문 + `infer.ts` 가 남긴 `flower:<slug>`)를 `score.ts` 의 `CUE_LEXICON` 으로 읽어 그 꽃의 `aestheticTags`·`colors`·`bloomMonths` 와 맞춘다. 신호별 몫은 이름 1.0 / 미감 .6 / 색 .5 / 계절 .3 이고 **들어온 신호끼리만** 나눈다(A 와 같은 문법).
  - **사전이 둘인 이유**: `infer.ts` 는 *형용사*("조용한")를 읽어 `recipientTraits`·`colorPrefs` 로 보내고 그것은 A 가 센다. `CUE_LEXICON` 은 *장면과 사건*("바다"·"졸업"·"다퉜어요")을 읽는다 — 에피소드 칸에 실제로 적히는 말이 이쪽이고, 형용사 사전으로는 잡히지 않는다. 두 사전이 겹치지 않으므로 P 는 A 가 못 보는 자리를 본다.
  - **읽어 낼 것이 없으면 P 는 중립값 0.5**다(0 이 아니다). 에피소드를 적지 않은 사용자의 전 후보가 같은 값을 받아 순위가 흔들리지 않으면서, "모르는 것"을 0점 취급해 상한을 깎지도 않는다. `SEASON_UNKNOWN` 과 같은 자리·같은 값이다.
  - **`recipientTraits`·`colorPrefs` 는 P 에서 다시 세지 않는다.** 그 둘은 A 의 재료이고, P 에서 한 번 더 세면 칩 하나가 점수를 두 번 움직이는 데다 이야기를 한 줄도 적지 않은 사용자의 P 가 후보마다 달라진다(= 위 중립 약속과 정면으로 부딪힌다).
  - 근거 RuleId 두 개: `SC_PERSONAL`(이야기와 결이 닿음) · `SC_MEMORY_FLOWER`(이야기에 그 꽃 이름이 있었음). **무엇이 걸렸는지는 문장에 적지 않는다** — 원문은 로그에도 설명에도 남기지 않는 §1.5j 금지선 그대로.
- **D(0.05) — 다양성**: `diversify()` 가 세 안을 고른 **뒤**, 각 안이 나머지와 얼마나 다른지를 가격대·미감·색 세 축의 평균으로 재서(0~1) 총점에 얹는다. 역할 분담이 명확하다 — **고르는 일은 그리디 재정렬(문턱)이, 말하는 일은 D 가중치(눈금)가** 한다. D 는 선정에 개입하지 않고 선정된 뒤의 총점만 바꾸며, 얹은 뒤 세 안을 총점 내림차순으로 다시 정렬한다.
- 그래서 **여섯 항이 전부 살아 있고 만점 조건에서 fitScore 100 이 실제로 나온다**(`tests/engine/score.test.ts` 가 증명). 단서 없는 입력의 3안은 구성이 그대로이고 절대 점수만 +8~9 오른다 — 바뀐 것은 예전에 **동점이던 자리의 순서**뿐이고, 그것을 가른 것이 D 다.
- 결과 프레이밍: 에피소드가 있으면 결과 상단에 "당신이 들려준 이야기를 담아 골랐어요" 1줄 + 매칭된 단서 칩(예: `조용한 사람` `튤립의 기억`) — 원문 전체를 다시 보여주는 건 괜찮음(클라이언트 상태)
- LLM 연동 시: memory_context로 전달(계약 이미 존재), 멘트에 직접 반영. **후퇴 금지선 유지: 원문은 로그·분석·DB 어디에도 저장 금지**(recommendation_results.private_payload에만, TTL 적용 — 원 설계 그대로)

**[2026-08-18 개정] AI 해석 층 — LLM 은 읽기만, 판단은 엔진**

사용자 확정: "성향+에피소드를 AI 로 처리하다가 API 다 쓰면 폴백으로 로컬 처리." 자유 서술 2필드를 모델에게 주고 시키는 일은 **하나뿐이다 — 우리 어휘로 번역.** 꽃을 고르는 일은 지금까지처럼 전부 엔진이 한다(결정적·설명 가능·안전 규칙은 코드 강제). 위 휴리스틱(`inferCuesFromText`)은 **지워지지 않았다** — 폴백 자리로 내려갔을 뿐이고 여전히 매 요청 돈다.

- **추출 계약**(`src/lib/llm/extract-contracts.ts`): 출력 여섯 칸이 전부 **우리 어휘**이고 자유 문자열 칸이 하나도 없다 — `recipientTraits`(RecipientTrait) · `colorPrefs`(flowers.csv colors 13색) · `personalCues`(엔진 `CUE_LEXICON` 낱말로 **정규화**된 장면어) · `mentionedFlowerIds`(flowers.csv id) · `pets`(cat|dog) · `fragranceSensitive`. 이 모양이 곧 "모델에게 넘긴 권한의 전부"다.
  - **어휘 밖 값은 칸마다 조용히 버린다 — 요청 전체 실패가 아니다.** 이 호출은 결과 화면 *앞*에 서므로, 한 칸이 어긋났다고 여섯 칸을 함께 버리면 사용자는 4초를 더 기다린 뒤 아무것도 못 얻는다.
  - **빈 값과 `null` 은 다르다.** 전부 걸러져 빈 값만 남는 것은 **성공**이고(모델의 "읽을 것이 없다"를 존중해 재시도하지 않는다), `null` 만 다음 프로바이더로 넘어간다.
- **프롬프트의 핵심 — 칸을 두 종류로 가른다**(2026-08-18 실측이 강제한 설계):
  - **취향 칸**(traits·colors·cues·flowers): 글이 그리는 결을 우리 어휘로 **옮기는 것이 일**이다. 틀려도 순위가 조금 흔들릴 뿐이다.
  - **안전 칸**(pets·fragranceSensitive): 이 둘은 **꽃을 후보에서 뺀다.** 글에 분명히 적혀 있을 때만 적고, 애매하면 비운다. 프롬프트가 반례를 예시로 못박는다("옆집 고양이" · "강아지를 좋아해요" · "제가 키워요" · "예전에 키우던" · "고양이 같은 사람").
  - ⚠ 처음에는 여섯 칸에 같은 강도로 "지어내지 마라"를 걸었더니 실모델이 "파도 소리를 좋아하는 사람이에요"에서 `recipientTraits` 를 **비운 채** 돌려줬다 — 규칙대로였지만 3안이 한 칸도 안 바뀌어 **기능이 아무 일도 하지 않았다.** 위험의 크기가 칸마다 다르다는 것이 빠져 있었다. 이 갈래를 지우면 기능이 조용히 죽거나(취향 칸까지 보수적) 위험해진다(안전 칸까지 관대).
- **폴백 사다리**: 기존 4단 체인 그대로(gemini→claude→clova→nvidia). 전부 실패·키 없음·타임아웃이면 `null` → **기존 로컬 사전 경로**. 배관은 `src/lib/llm/chain.ts` 한 벌을 멘트 생성과 나눠 쓴다(체인이 두 벌이면 서로 다르게 늙는다).
  - **예산 4초** — 멘트의 10초와 **별개**다. 멘트는 결과 화면이 선 *뒤* 흘러 들어오지만(스트리밍), 추출은 엔진보다 *앞*에 서서 그 시간이 곧 빈 화면 시간이다.
  - **자유 서술이 둘 다 비면 부르지 않는다**(지연 0). 칩만 고른 사용자의 속도는 이 기능 이전과 같다.
- **병합**(`prepareResult` 의 `resolveCues`): 분위기·색은 기존 추론과 **같은 자리에서 합집합**이고 직접 고른 칩이 언제나 앞이다. 반려동물·향은 **안전 쪽이 이긴다**(칩과 글의 합집합, 민감이 이기면 향 선호가 꺼진다). 꽃 이름도 **합집합**이다.
  - ⚠ 꽃 이름은 처음에 "한 소스만"(AI 성공 시 AI)으로 두었다가 **되돌렸다.** 정밀도를 잘못 봤기 때문이다 — 사전은 문자 그대로의 이름 매칭이라 오탐이 없고, 글에 "수국"이 있는데 AI 가 놓쳤다면 그건 중의성이 아니라 그냥 누락이다. 한 소스 규칙은 그 경우 사용자가 분명히 부른 이름을 조용히 버리고 `SC_MEMORY_FLOWER` 가점과 §1.5d 한 줄을 함께 잃는다. 합집합이면 걱정하던 "두 말"도 오히려 사라진다(놓친 이름이 없어져 단서 칩과 §1.5d 한 줄이 같은 목록을 본다). 검증은 그대로 둘이다: AI 쪽은 `EXTRACT_FLOWER_IDS`, 실재는 `mentionedFlowerIds` 의 카탈로그 대조.
- **읽어 낸 안전 신호를 화면이 말한다**: AI 가 읽은 반려동물·향 때문에 후보가 줄었으면 맥락 칩 줄에 `반려묘와 살아요 · 이야기에서 읽었어요` 한 칸이 선다(`ResultDraft.readChips` — `ownWords` 와 같은 문법의 표식 배열이고, 화면은 그 칸만 점선·투명 바탕으로 갈라 세운다). 서는 조건은 셋이다: ⑴ 그 신호가 AI 에게서 왔다(칩으로 고른 것이면 이미 그 라벨이 서 있다) ⑵ 그 신호를 빼고 다시 세면 **제외가 실제로 줄어든다** ⑶ 규칙별로 따로 센다(반려동물이 뺐는데 향 칩이 서지 않게).
  - ⚠ **읽기만 하고 아무 꽃도 안 빠졌으면 세우지 않는다** — 일어나지 않은 일을 알리는 칩이 되고, "네 글에서 반려동물을 찾아냈다"는 사실만 자랑하게 된다. 칩 낱말은 `RECIPIENT_CHIPS` 의 라벨을 그대로 쓴다(같은 사실을 두 가지 말로 부르지 않는다). **신호의 종류만 말하고 원문은 되비추지 않는다.**
- **멘트만 다시 받기는 해석을 부르지 않는다**(`새로 받기` · `짧게/보통`): 그 자리는 3안이 이미 화면에 서 있고 바뀌는 것은 멘트뿐이다. 대신 화면이 들고 있는 3안의 꽃 id 를 함께 보내고 서버가 첫 안을 되돌린다(`pinFirstPick`). 꽃 id 는 우리 어휘라 자유 서술과 달리 실어 보내도 되는 값이고, 공개 엔드포인트로 들어오므로 **모양(zod)과 카탈로그 실재** 두 문을 통과시킨 뒤 어긋나면 조용히 무시한다(멘트의 힌트일 뿐 결과의 전제가 아니다).
  - ⚠ 잠깐 이 경로에서도 해석을 다시 불렀다. 다시 계산한 첫 안이 화면과 어긋날까 봐서였는데 대가가 컸다 — 새로 받기마다 4초가 더 붙고, 해석이 흔들리면 어차피 또 어긋난다. **답은 다시 읽는 것이 아니라 화면이 아는 것을 넘겨받는 것이다.** 2026-08-18 실측: 같은 답변에서 해석 경로의 첫 안은 `프리지아`, 사전만으로 다시 고른 첫 안은 `알스트로메리아` — 핀이 없으면 새 멘트가 화면에 없는 꽃을 이야기한다.
- **정적 데모**: `prepareResult` 의 세 번째 인자를 넘기지 않는다 → 언제나 로컬 경로. 브라우저에 키를 둘 수 없다는 기존 금지선이 그대로 "API 다 쓰면 로컬 폴백"의 데모판이 된다. 데모 쌍둥이 파일은 한 글자도 바뀌지 않았다.
- **프라이버시(협상 불가)**: 원문은 **LLM 요청 본문에만** 산다 — 로그·에러 메시지·URL·저장소 어디에도 없다. 추출 결과(어휘 값)도 저장하지 않는다. 계약이 자유 문자열 칸을 열어 두지 않으므로 모델이 원문을 되돌려 보내도 반환값에 남지 않는다. `tests/llm/extract.test.ts` 가 fetch mock 으로 이를 증명한다(요청 본문에는 있고 · URL·로그에는 없고 · 실패 경로를 지나가도 없다).
- **화면**: 자유 서술을 적은 사람의 제출 버튼만 `적어 주신 이야기를 읽고 있어요…` 로 바뀐다(§1.5d). 아무것도 안 적은 사람에게는 읽는 걸음이 아예 없으므로 지금까지의 문구 그대로다 — 없는 일을 하고 있다고 말하지 않는다.
- **실측(2026-08-18, gemini-flash-lite)**: 추출 1.3~1.6초. "파도 소리를 좋아하는 사람이에요"(사전이 못 읽는 표현) → `traits:[calm]`·`cues:[파도]` → 3안이 `alstroemeria·geranium·freesia` 에서 `freesia·hydrangea·alstroemeria` 로 바뀌고 단서 칩 `차분한 분위기` 가 선다. 키 무효화 시 0ms 에 `null` → 사전 경로 결과와 완전히 동일. 과잉 추출 반례 10건 전수 통과(진짜 "반려묘와 함께 살아요"만 `pets:[cat]`). 제출 지연: 자유 서술 없음 0.3초 / 있음 2.0~2.5초. **새로 받기 2.4초**(재추출을 걷어내기 전이었다면 +1.6초).

#### 1.5k-2 도감 상세의 「문학 속의 이 꽃」 (2026-08-18 · B-5)

**데이터가 화면을 앞서 있던 자리를 메운다.** `quotes.csv` 의 문학 발췌 **86행(36종)** 은 여태 추천 결과 화면에서만 보였다 — 추천을 거치지 않고 그 꽃을 알아보러 곧장 들어온 사람에게는 없는 자료였던 셈이다(「사러 가기」가 겪은 것과 같은 모양의 구멍이고, 같은 날 같은 판단으로 메웠다).

| | 결과 화면 (§1.5k) | **도감 상세 (§1.5k-2)** |
|---|---|---|
| 위계 | 멘트 아래 **곁들임** | 제 **구획**(h2 + 편수) |
| 자리 | 멘트 카드 바로 밑 | **이야기 아래 · 상황(「이런 날 건네보세요」) 위** |
| 분량 | 대표 1편 + `다른 문학도 보기` 로 이전/다음 | **전 행**(아카이브). 5편 초과분만 `<details>` 로 접음 |
| 차례 | `orderLiterature` | **같은 함수**(intent 는 `just_because` — 도감에 상황이 없다) |
| 거르기 | 대표 이야기와 같은 작품·「함께 담을 한 줄」과 같은 작가 제외 | **거르지 않음**(그 두 자리가 도감에 없다) |
| 조판 | `.lit*`(flow.module.css) | 같은 결, **값은 flowers.module.css 에 제 것으로** |

- **자리의 근거**: 꽃말 → 이야기 → 문학까지가 이 화면에서 **읽을 것**이고, 상황 · 참고 · 사러 가기부터가 **할 것**이다. 문학을 행동 구획 뒤로 내리면 읽던 사람이 그 구획을 지나 다시 읽을 것으로 돌아와야 한다. 상세 위계는 그래서 **꽃(실사 → 세밀화) → 꽃말 → 이야기 → 문학 → 상황 → 참고(작게) → 사러 가기 → CTA** 가 된다.
- **차례를 도감이 다시 정하지 않는다**(협상 불가). 정렬을 베끼면 같은 꽃에서 두 화면이 다른 편을 앞세우고, 같은 작가의 연작이 붙어 나오는 것(베르길리우스 3행·셸리의 인접 연)도 도감에서만 되살아난다. 도감 쪽 코드에는 정렬이 한 줄도 없고 `orderLiterature`(flow/labels.ts)만 부른다.
- **없는 23종에는 구획 자체가 없다.** 근대에 명명돼 고전 문학에 등장하지 않는 꽃들이다(프리지아 · 거베라 · 안개꽃 · 포인세티아 · 달리아 …). 그 자리를 편집팀 문장으로 메우지 않는 것이 §1.5e "검증된 인용만" 이고, 빈 섹션 미렌더는 이 화면의 기존 규범이다(세밀화 · 상황 · 탄생화 각주가 전부 같은 규칙).
- **접는 선은 5편**. 실제로 넘는 것은 빨간 장미(9편) 하나뿐이지만 상수로 둔다 — 발췌는 배치로 늘어나는 표라 다음 배치가 들어오면 화면이 저절로 접는다. 도구는 `<details>`(크레딧 폴드와 같은 규칙 — JS 없이 열리고 44px 타깃).
- **대표 케이스 둘**(실물 렌더 확인 대상): 김소월 〈진달래꽃〉은 1925 초판 표기(`진달내꼿` · `노힌그꼿츨` · `삽분히즈려밟고` · 한자 `寧邊`·`藥山`)를 원문 칸에 그대로 세우고, 매화 한시 3편(왕안석 · 임포 · 이황)은 한문 원문을 병기한다. **화면 사정으로 원문을 고치지 마라** — 옛한글 자모는 이미 렌더 가능한 현대 완성형으로 옮겨 적재돼 있고(어휘 · 어순 · 행갈이 · 종성 불변), 복원 대조표는 `docs/literature-research-2.md` §6 에 있다. 옮겼다는 사실은 `translator=dearbloom` → 각주 `옮김: dearbloom` 과 `caveat` 가 화면에서 직접 말한다.
- **caveat 는 각주 중에서도 따로 선다**(왼쪽 선). 진달래와 철쭉이 다른 종이라는 것, 매화가 매실나무의 꽃이라는 것 — 밝히지 않으면 이 화면이 틀린 정보를 주는 화면이 된다.
- 회귀 가드: `tests/components/flowers-literature.test.ts`(36/23 갈림 · 86행 전수 · 작가 인터리브 · 초판 표기 · caveat 전수 · 배치 순서 · 뷰 조립 몸통이 결과 화면과 글자까지 같은지).

- **`1~2만 원대` 는 `3만 원 미만` 과 같은 band 1 로 떨어진다.** 이전 판(2026-08-15)은 바로 이 이유로 저가 구간을 쪼개지 않기로 했었는데, 뒤집는다 — 두 선택지가 고르는 꽃이 같더라도 **고르는 사람의 말이 다르다.** "3만 원 미만"은 상한을 말하고 "1~2만 원대"는 실제로 쥔 돈을 말한다. 엔진이 가를 수 없는 구간을 화면이 갈라 두는 것이므로 **추천 결과가 같은 것은 버그가 아니다**(`BUDGET_CHOICES` 주석·테스트가 이 사실을 못박는다). price_band 가 1·2·3 뿐인 한 이 아래를 더 쪼개도 고를 수 있는 꽃은 늘지 않는다.
- `기타` 를 고르면 자유 한 줄(**80자**, 선택)이 열린다. 예산 필터를 걸지 않으므로 전 가격대가 후보로 남고, 화면도 그렇게 말한다("값을 정하지 않으면 모든 가격대의 꽃을 함께 보여드릴게요").
- ⚠ **예산 한 줄은 LLM 계약에 담지 않는다.** 프롬프트 절대 규칙 3 이 "가격을 문장에 쓰지 않는다"이고, 금액이 적힌 글을 `<자료>` 에 실으면 모델을 그 금지선 앞으로 데려다 놓는 셈이 된다(반려동물·향 민감 칩을 `messageNotes` 에서 빼는 것과 같은 판단 — ③ 참고). 쓰임은 **결과 맥락 칩 하나뿐**이고 저장하지 않는다. 비워 두면 칩도 세우지 않는다.

**⑥ 데스크톱 해체 — 질문·`/groups` 도 웹페이지다** (2026-08-16 사용자 피드백: "추천 시작·여러 분께를 누르면 웹에서 앱 화면으로 바뀐다")

결과 화면은 이미 768/1024 에서 폰 프레임을 버렸지만 **질문 화면과 `/groups` 는 아직 앱이었다.** `/groups` 는 문자 그대로 430px 캔버스에 radius 40px + 네 겹 그림자를 둘러 화면 한가운데 띄워 두었고, 질문 화면은 캔버스는 사라졌어도 묻는 말과 고르는 칸이 한 줄로 쌓인 좁은 기둥이라 앱 위저드로 읽혔다.

- **질문 화면 (1024px↑)**: 결과와 **같은 1120px 칼럼**에 2단. 좌단(320px, sticky) = 묻는 말(오버라인·제목·리드), 우단(≈690~710px) = 답. 헤어라인 한 줄로 가른다. 고정 푸터바는 768px↑에서 이미 본문 흐름 버튼이고, 1024px↑에서는 **우단 시작점에 맞춰** 답 바로 아래에 선다(왼쪽 끝에 서면 2단이 도로 무너져 보인다). 칩·프리셋 줄은 넓어진 우단을 그대로 쓴다.
- **`/groups` (768px↑)**: 폰 캔버스·라운드·그림자 제거, 셸이 추천 플로우 `.frame` 과 같은 다크 그린 워시를 깔고, 상단바 = 사이트 헤더, 본문 = 1120px 중앙 칼럼. **1024px↑에서는 왼쪽 입력(마음·명단) / 오른쪽 결과(`.resultCol`) 2단** — 이 화면은 "적고 → 눌러서 → 아래에 나온 것을 본다"가 아니라 적으면서 결과를 함께 보는 화면이고, 세로로만 쌓으면 명단이 길어질수록 결과가 화면 밖으로 밀린다. 두 섹션(결과 패널·카드에 담기)을 한 래퍼로 감싸는 이유는 단을 가르는 **헤어라인이 한 줄이어야** 하기 때문이다.
- **모바일(<768px)은 무회귀.** 두 화면 모두 새 래퍼가 그냥 블록이라 DOM 순서 = 지금까지의 한 칼럼 순서 그대로다.
- 검증: 390·768·1280·1536 에서 위저드 5걸음 + 결과, `/groups` 완주 — 가로 스크롤 0, 데스크톱에 좁은 부유 캔버스 없음, 단계 포커스(`#q-title`)·live region 무회귀.

> `이 꽃이 탄생화로 놓인 날 — 3월 21일 · 10월 9일`  `널리 통하는 탄생화 표에서 가져왔어요.`

**⑤ 2단 티어 — 정식 도감과 탄생화 사전 (2026-08-16 사용자: "탄생화를 가져왔으면 꽃이 365개 이상이어야 하는 거 아니야?")**

맞는 지적이다. 탄생화는 366일이고 그 표가 부르는 이름은 **303가지**인데, 도감에 실린 꽃은 32종뿐이었다. 두 숫자가 한 화면에 있으면서 설명이 없으면 도감이 뭔가를 숨기는 것처럼 읽힌다. 그렇다고 303가지를 전부 "도감의 꽃"으로 올릴 수는 없다 — 정식 도감 한 종에는 색깔별 꽃말(출처 포함)·이야기·반려동물 안전성·실사·도판이 붙어 있고, 표에서 온 이름에는 **이름과 꽃말 한 줄**밖에 없다. 그래서 합치지 않고 **층을 나눈다.**

| | **정식 도감** (47종 — 2026-08-16 배치 1로 32→47) | **탄생화 사전** (366일 · 미보유 이름들) |
|---|---|---|
| 근거 | `content/flowers.csv` + meanings·stories·pet_safety | `content/birth_flowers.csv` 한 표 |
| 갖는 것 | 색깔별 꽃말(출처별)·이야기·안전성·실사·도판·상황 | 이름 · 영문명/학명(있는 날만) · 꽃말 한 줄 · 놓인 날 · 출처 |
| 열람 | `/flowers/[slug]` **상세 페이지** | 사전 **시트**(라이트) — 페이지를 만들지 않는다 |
| 화면 표시 | 목록 줄 오른쪽 `도감`(액센트) + 실사 썸네일 | 목록 줄 오른쪽 `사전`(흐림) + **빈 액자** |
| 검증 | 반려동물 안전성까지 확인 | **미확인** — 그 사실을 시트가 말한다 |

- **왜 사전 항목에 상세 페이지를 주지 않나**: 여섯 줄로 `/flowers/[slug]` 같은 한 장을 세우면 정식 도감과 **같은 무게로 읽힌다**. 사진도 이야기도 안전성도 없는 페이지가 도감 상세인 척하게 된다.
- **티어 고지 두 줄**(사전 시트, §1.5d 톤). 원본은 `src/components/flowers/birth-copy.ts` — 화면마다 새로 짓지 않는다.
  > `아직 도감에 들이지 못한 꽃이에요 — 이름과 꽃말부터 먼저 건네요.`
  > `색깔별 꽃말과 이야기, 반려동물 안전성은 아직 확인하지 못했어요.`
  둘째 줄이 이 블록의 존재 이유다. **반려동물 안전성은 §1.5h 가 직설을 요구하는 항목**이고, 확인하지 않은 것을 말하지 않으면 사전 항목이 "안전한 꽃"으로 오해된다. 이 블록만 면(배경+보더)을 갖는 이유도 그것이다 — 건너뛰어 읽히면 안 된다.
- **사진을 지어내지 않는다.** 매칭되지 않은 줄은 **빈 액자**(점선 44×44)로 남긴다. 아이콘·색면·다른 꽃 사진으로 채우면 두 티어가 같은 무게로 보인다.
- **인트로 통계도 두 층으로 말한다**: `47 종 · 정식 도감` / `366 일 · 탄생화 사전` / 꽃말 / 이야기. 인트로에서 두 층을 말하는 것은 **이 라벨까지**다.
- ⚠ **차이를 설명하는 문단은 인트로가 아니라 사전 구획 안에 둔다**(`.dictTierNote` — 면 없음, 랜딩 각주와 같은 판단). 인트로는 `<main>` **위**라, 웹폰트가 늦게 도착한 로드에서 그 문단의 줄 수가 바뀌면 아래 화면 전체가 밀린다 — 2026-08-16 실측으로 1280px CLS 가 **0.005 → 0.17** 로 뛰었고(6회 중 재현), 문단을 사전 구획으로 옮기자 0 으로 돌아왔다. 첫 화면 밖에서 일어나는 재배치는 이동으로 세어지지 않는다. **인트로에 설명 문단을 덧붙이지 마라.**
- 그 문단의 **마지막 문장이 ①의 워딩 대전제**다(`BIRTH_SOURCE_NOTE` 를 그대로 이어 붙인다).

*⑤-2 열람 화면 — 도감 `/flowers` 사전 구획*

생일 꽃 찾기 **아래**, 하단 CTA **위**. 이름 검색이 "아는 꽃", 생일 찾기가 "내 날짜 하루"라면 여기는 **표 전체를 훑는** 문이다.

- **달 칩 12개**(§1.6b 칩 규격 — pill h44 고정, 선택은 `--ctrl-on` 짝 채움 **하나로만**). 390px 에서 세 줄로 접힌다.
- **처음에는 아무 달도 펼치지 않는다.** 자동으로 한 달을 열면 `/flowers` 를 여는 모든 사람이 쓰지도 않을 9KB 남짓과 썸네일 대여섯 장을 받는다. **그 한 번의 클릭이 페이로드의 문지기다.** (`new Date()` 로 이번 달을 정하면 SSR·CSR 이 갈리는 문제도 따라온다.)
- **목록은 하루 한 줄**: 일 · 썸네일(또는 빈 액자) · 이름/꽃말 · 티어 표시. 검색 결과(`.results`)와 **같은 분기**로 접는다(720px 2단 / 1040px 3단) — 31줄을 한 칼럼에 세우면 2,000px 이 넘고, 한 화면에서 목록이 두 가지 방식으로 접히면 그것부터 읽힌다.
- **매칭 줄은 `<a>`, 미매칭 줄은 `<button>`.** 겉모습을 같게 두고 클릭 동작만 바꾸면 화면 낭독기에서 둘이 구별되지 않는다 — 하나는 "링크", 하나는 "버튼"으로 들려야 어디로 가는지 알 수 있다.
- **사전 시트**(라이트 상세): 날짜 · 이름 · 영문명/학명 · 꽃말 · **표에서 이 이름이 놓인 다른 날** · 티어 고지 두 줄 · 표 출처 링크 · 계보 각주. 규격은 `/stories` `StorySheet` 그대로(모바일 바텀 시트 → 768px↑ 가운데 카드, `aria-modal`·포커스 트랩·ESC·배경 탭·body 스크롤 잠금).
  - `StorySheet` 와 달리 **열 때 다시 가져오지 않는다.** 사전 한 줄이 통째로 200바이트 남짓이라 이미 받은 달치 목록 안에 시트가 쓸 것이 전부 있다.
  - `표에서 이 이름이 놓인 다른 날` 은 **이름**으로 역조회한다(`birthDaysOfName`). 309일에는 `flowerId` 가 없어 이름이 유일한 신원이기 때문이다. ⚠ 도감 상세(④)는 계속 `birthDaysOf`(flowerId)를 쓴다 — 그쪽의 신원은 카탈로그의 꽃이고 표 이름과 다를 수 있다(`노랑수선화` ↔ `수선화`). 두 함수를 바꿔 쓰지 마라.
- **데이터 경로: 서버 액션 `listBirthMonth(month)`** — 자르는 단위가 **한 달**이다. 366행 통짜(64.8KB / gzip 9.2KB)를 첫 응답에 얹지 않는다는 ③의 규율을 이 모양이 강제한다: 화면이 받을 수 있는 가장 큰 덩어리가 31행이다.
  - **실측**(2026-08-16, `JSON.stringify` 기준): 한 달 **8.2~10.0KB / gzip 1.4~1.8KB**(2월 8.32 · 1월 9.99). 12달을 다 눌러도 111KB / gzip 19.9KB 지만, 그렇게 훑는 사람은 없다 — 사람이 여는 것은 자기 달과 선물할 사람의 달이다.
  - 한 줄이 출처 URL(70B)을 그대로 들고 있어 raw 의 약 1/4 이 같은 문자열의 반복이다. **인덱스로 접지 않았다** — 전송은 압축돼 나가므로 그 반복이 실제로 무는 값은 gzip 기준 0.2KB 남짓인데, 병렬 배열과 첨자는 읽는 사람이 매번 되짚어야 하는 비용이다. 압축이 지우는 중복을 코드로 지우지 마라.
- ⚠ **액션을 늘리면 정적 데모 쌍둥이도 늘려라** — `src/lib/demo/flowers-actions.ts`. `NEXT_PUBLIC_STATIC_DEMO=1` 빌드는 `@/app/flowers/actions` 를 **통째로** 그 파일로 갈아 끼우므로(turbopack `resolveAlias`), 앱에만 있는 export 는 데모에서 `undefined` 가 되고 `npm run build:static` 이 깨진다. 값은 브라우저에서 다시 조립하지 말고 빌드 타임에 **서버와 같은 함수**(`buildBirthMonth`)로 굳힌다(`scripts/build-demo-catalog.mjs` → `data/birth-months.ts`).

**⑥ 승격 파이프라인 — 사전에서 정식 도감으로**

2단 티어는 **영구 분리가 아니라 대기열**이다. 사전 303가지 이름은 "싣지 않기로 한 꽃"이 아니라 "아직 검증하지 못한 꽃"이고, 주간 콘텐츠 루틴(`.github/` 워크플로 · `docs/` 콘텐츠 운영)이 그중 몇 종씩 정식 도감으로 올린다.

한 항목이 정식 도감으로 올라오려면 **네 가지가 다 있어야 한다** — 하나라도 비면 승격하지 않고 사전에 그대로 둔다(반쪽짜리 도감 항목을 만들지 않는다):

1. `flowers.csv` 한 행 — 학명·색·개화월·향·가격대까지. **학명이 종을 특정해야 한다**(표의 이름만으로 종이 갈리는 경우가 있다 — 조사 문서 §8).
2. `meanings.csv` 최소 한 행 — **출처 URL 필수.** 출처 없는 꽃말은 싣지 않는다(§1.5).
3. `pet_safety.csv` — 개·고양이 두 종 전부. **여기가 승격의 병목이다.** 안전성을 확인하지 못한 꽃은 도감에 올리지 않는다(§1.5h).
4. 실사 한 장(`src/lib/photos`) — 승인 소스(Unsplash·Pexels)에서, **종이 동정되는 컷**으로.

승격하면 화면은 **저절로** 따라온다. `birth_flowers.csv` 의 `flower_id` 한 칸을 채우는 순간:
- 사전 목록 줄이 `사전`(빈 액자) → `도감`(썸네일 + 상세 링크)으로 바뀌고,
- 생일 꽃 찾기 결과 카드에 `도감에서 … 보기` 버튼이 서고,
- 도감 상세에 `이 꽃이 탄생화로 놓인 날` 줄이 생기고(④),
- 인트로 통계의 `정식 도감 N종` 이 하나 올라간다.

즉 **승격 작업은 CSV 편집이고 화면 코드는 손대지 않는다.** 숫자를 상수로 베껴 두지 않고 전부 표에서 세는 이유가 이것이다(`birthSpeciesCount`·`birthCalendar`·`flowers.length`).

**⑦ 로드맵 — 아직 하지 않은 것**

- `editorial_note`(158행)는 **화면 비노출**이다. 종 차이처럼 사용자에게 알려야 하는 사실을 내보내려면 `quotes.caveat` 같은 별도 컬럼이 필요하다 — 지금은 없다(조사 문서 §8-4).
- 월 단위 탄생화(영국식·미국식)는 싣지 않았다. 날짜별 표와 출전이 다른 계보라 섞으면 둘 다 흐려진다.
- 사전에는 **검색이 없다**(달로만 훑는다). 303가지 이름을 이름으로 찾게 하려면 색인을 클라이언트로 내려보내야 하는데, 그것이 곧 ③이 막아 둔 "366행 통짜"다. 필요해지면 검색도 서버 액션으로 간다.
- 사전 시트에는 **이전/다음이 없다.** 한 항목이 여섯 줄이라 넘겨 볼 이유가 크지 않고, 넘기려면 목록으로 돌아가는 편이 자기 날짜를 찾는 동선에 맞다.

### 1.5o 비밀 편지 — 기기 저장 단계에서 화면이 말해야 하는 것 (2026-08-17 감사 P0-1)

> §1.5m ①(탄생화 워딩 대전제)과 같은 종류의 절이다. 디자인 규격이 아니라 **정직함의 선**이고, 코드 주석이 아니라 테스트가 지킨다.

**무엇이 문제였나.** `/letter` 는 `받으신 편지 번호를 적어 주세요. 번호를 아는 분만 그 편지를 열 수 있어요.` 라고 말했다. 그런데 편지는 **만든 사람의 브라우저에만** 있다(`src/lib/letters/store.ts` — 그 파일이 스스로 "이 기능의 유일한 금지선"이라 적어 둔 사실). 번호를 받아 찾아온 사람의 기기에는 애초에 사본이 없으므로 **어떤 번호도 맞을 수 없다.** 그런데 화면은 ⑴ 번호가 열쇠라고 말하고 ⑵ 실패하면 `한 글자씩 다시 봐 주시겠어요?` 라며 오타를 의심시키고 ⑶ 다섯 번 어긋나면 20초를 기다리게 했다. `이 기기에만 남아 있어요` 고지는 있었지만 **`mine.length > 0` 분기 안**에 있어서, 편지를 만든 적 없는 사람 — 즉 그 문장이 가장 필요한 사람 — 에게는 한 번도 보이지 않았다. 구조적으로 불가능한 일을 사용자 탓으로 돌린 셈이다.

**규범 — 이 단계에서 화면은 다음을 말한다.**

| # | 규범 | 어긋난 예 |
|---|---|---|
| ① | **어디에 있는지**: 편지는 우리 서버가 아니라 쓴 사람의 브라우저에 남는다 | (침묵) |
| ② | **그래서 지금 어떤지**: 편지를 쓴 그 기기에서만 열린다 | `번호를 아는 분만 열 수 있어요` |
| ③ | **앞으로 어떻게 되는지**: 어디서든 여는 길은 준비 중이다. 없는 기능을 있다고 하지 않되, 끝이라고도 하지 않는다 | `서비스가 문을 열면 어디서든 열어볼 수 있게 돼요`(시점을 약속한다) |

**자리 — 어디에 서는가.** 규범보다 자리가 더 자주 무너진다.

- **여는 화면**: `편지 열기` 패널 안, **번호 칸 위**. **편지 목록 유무와 무관하게** 언제나 선다. ⚠ `mine.length` 같은 목록 상태를 이 패널에 들이지 마라 — 그 조건이 들어오는 순간 고지가 다시 "편지를 가진 사람에게만" 보일 길이 열린다. 시도한 **뒤에** 읽히면 늦으므로 폼 아래로 내리지도 않는다.
- **만드는 화면**: 폼 맨 위 안내 + **저장 완료 화면**. 완료 화면이 더 중요한 자리다 — 사람이 번호를 복사해 건네는 순간이 거기다.
- **들어오는 문**: `/letter` 인트로와 메타데이터. 화면 안쪽만 정직하고 문이 옛말을 하면 같은 거짓말이다.
- 면(배경+보더)을 갖는다 — 사전 티어 고지(§1.5m ⑤)와 같은 판단이다. 건너뛰어 읽히면 안 된다.

**실패와 기다림.** 20초 잠금은 **유지한다**(무차별 대입을 늦추는 습관 — `LetterEntrance` 머리말). 다만 문구는 오타만 의심시키지 않고 **다른 기기에서 쓴 편지라면 번호가 맞아도 열리지 않는다**는 가능성을 함께 말한다. 기다린 뒤에도 열리지 않을 수 있다는 것을 숨기면 기다림 자체가 두 번째 거짓말이 된다. ⚠ 못 찾은 이유를 나누어 말하는 것은 여전히 금지다(형식 오류와 못 찾음이 한 문장인 것은 `store.findByCode` 가 정한 선이다 — 나누면 번호를 맞히려는 사람에게 힌트가 된다).

**문구 원본은 `src/components/letter/copy.ts` 한 파일.** 화면마다 새로 짓지 않는다(`birth-copy.ts` 와 같은 장치). 톤은 §1.5d 해요체 그대로, 겁주지 않고 담담하게. 개발 어휘는 `브라우저 저장소` 까지가 지금의 결이고 그 아래(`localStorage`·`Supabase`·`API`)로는 내려가지 않는다.

⚠ **Supabase 로 넘어가는 날, 저장소보다 이 문구를 먼저 고친다.** 위 문장들은 "지금 이 단계의 사실"이지 서비스의 약속이 아니다 — `/partners` 의 `NO_AFFILIATION` 과 같은 성격의 상수다. `SupabaseLetterStore` 를 끼우는 순간 이 파일의 문장은 **먼저 거짓이 된다.** `tests/letters/device-notice.test.ts` 가 그날 빨개지도록 세워 두었으니, 빨간 것을 지우지 말고 문구부터 고쳐라.

### 1.5p 오늘의 꽃 — 개화 폭 가중 (2026-08-17 감사 P1-2)

365일 전수 실행에서 배정이 **26:1 로 쏠렸다**(국화 26일 대 벚꽃·물망초·과꽃 각 1일). 버그가 아니라 구조였다 — 후보군은 달마다 새로 꾸려지므로(`today.ts` `candidatesFor`) 개화월이 넓은 꽃은 열두 번의 추첨에 다 끼고, 한 달만 피는 꽃은 한 번만 낀다. HRW 해시는 후보군 **안에서** 균등할 뿐 연간 노출을 고르게 하지 않는다.

- **처방**: HRW 점수에 **개화 폭(그 꽃의 개화월 수)의 역수**를 가중치로 넣는다. 가중 랑데부 해싱의 표준형(`u^(1/w)`, 최댓값 승리)에 `w = 1/개화폭` 을 넣은 식이라 그날 1등이 될 확률이 정확히 가중치에 비례한다.
- **깨면 안 되는 셋**: 결정성(같은 날짜 → 같은 꽃) · 연속 반복 0 · 제철 우선. 셋 다 후보군 선정과 사슬 로직을 건드리지 않았으므로 그대로다.
- ⚠ **가중치는 꽃 자신의 개화월만 센다.** 카탈로그를 훑어 "실제로 후보로 선 달"을 세면 더 정확하지만, 그 순간 한 꽃의 가중치가 다른 꽃의 존재에 매여 HRW 가 지키는 성질(꽃이 늘고 줄어도 남은 날의 배정이 그대로)이 무너진다. 정확도보다 그 안정성이 먼저다.
- ⚠ **`Math.log`·`Math.pow` 를 쓰지 않는다.** 두 함수의 마지막 자리는 엔진마다 다를 수 있어 서버와 브라우저가 같은 날 다른 꽃을 고를 수 있다. 개화 폭은 1~12 정수라 곱셈 반복이면 되고, IEEE-754 곱셈은 어디서나 같은 값을 낸다.
- **실측**(59종 카탈로그 · 2026년 365일): 표준편차 **4.84 → 3.06**, 한 해에 한 번도 안 나오는 꽃 **1종 → 0종**, 최다 21일 → 18일. 남은 격차(최다 18 : 최소 1)는 **달마다 제철 꽃 수가 다르기 때문**이다 — 4월은 후보 31종인데 11월은 10종이라, 11월에만 피는 꽃은 구조적으로 자주 나온다. 그것이 제철 우선의 결과이므로 더 누르지 않는다.
- **테스트는 특정 꽃 이름이나 실데이터 일수를 단정하지 않는다**(도감이 자라면 그 숫자는 움직인다). 종 수와 무관하게 성립하는 성질만 본다 — 같은 후보군에서 좁은 쪽이 자주 나오는가, 개화 폭이 다른 무리끼리 연간 몫이 비슷해지는가(`tests/engine/today.test.ts` §4b).

### 1.5q 「읽을거리」 — 바깥에서 골라 온 것 (2026-08-18 개통)

사용자 요구는 "꽃 관련 아티클이나 새로 올라오는 유명한 내용을 볼 수 있는 섹터" + "꽃 축제 소개 + 재미 + 감성적인 + 카테고리 분류"였다. 화면은 `/reads`, 내비 라벨은 **「읽을거리」**. 원장은 `content/reads.csv` 54건(축제·전시 20 · 글 13 · 트렌드 11 · 실용 10)이고, 선정·기각의 단일 원본은 **`docs/reads-research.md`** 다 — 한 줄 더하기 전에 그 문서의 선정 기준 여섯을 먼저 본다.

**이 섹션이 하지 않는 것 세 가지.** 이게 규격의 절반이다.

| 하지 않는다 | 근거 |
|---|---|
| **크롤링·본문 저장** | 기사 본문을 긁어 저장·재배포하면 인용이 아니라 복제다. 싣는 것은 제목·출처·**우리가 쓴 한 줄**(`summary_ko`)·링크뿐이고, 스키마에 본문·요약 원문 칸 자체가 없다(조사 문서 §1) |
| **남의 이미지** | `reads.csv` 에 이미지 URL 칸을 두지 않았다. 매거진 썸네일·기사 사진 핫링크 금지. 위계는 크기·여백·헤어라인이 만든다. ⚠ 2026-08-18 에 카드 왼쪽 액자가 붙었지만 이 금지선은 그대로다 — 거기 서는 그림은 **우리 자체 호스팅 도판**뿐이고 원장에는 여전히 이미지 칸이 없다(§1.5u) |
| **상세 페이지** | 목적지는 원문이다. 우리 화면에 한 겹을 더 세우면 그 겹은 남의 글을 대신 말하는 자리가 된다 |

**만료 거르기 — 브라우저에서.** 이 섹션의 최대 위험은 **지난 행사가 화면에 남는 것**이다. 판정표는 조사 문서 §6-1 그대로(`끝남 = ends_at < 오늘` · `아직 = starts_at > 오늘` · **경계는 포함** — 오늘이 마지막 날인 행사는 아직 갈 수 있다).

- **거르는 자리는 서버가 아니라 브라우저다.** 정적 배포에서 서버 렌더로 거르면 배포한 날의 "오늘"이 HTML 에 박혀, 10월에 배포한 사이트가 12월에도 10월 기준으로 행사를 보여 준다(§7-2). 구현은 `src/components/reads/expiry.ts` + `ReadsBoard` 의 `useSyncExternalStore`(서버 스냅숏 `null` / 클라이언트 스냅숏 KST 오늘)다 — `useState`+`useEffect` 로 되돌리면 하이드레이션이 어긋나거나 이펙트 안 setState 가 된다.
- **JS 가 꺼져도 목록 자체는 보인다.** 거르기만 JS 의 몫이다. 대가는 첫 페인트에 지난 행사가 스쳤다 사라지는 것인데, 반대로 마운트 전까지 감추면 JS 없는 사람에게 **빈 화면**이 남는다.
- 날짜 비교는 **KST 날짜 문자열끼리** 한다(`Date` 객체 비교는 UTC 자정 경계에서 하루가 밀린다). 기기 시계를 믿는 셈이라는 것을 알고 쓴다 — 최악이 "지난 축제 하나가 남는 것"이라 서버를 세우는 비용과 맞지 않는다.
- **월 단위로만 공지된 행사는 달로 말한다.** 원장이 말일을 채워 둔 행을 「9월 30일까지」라고 쓰면 없는 정확성을 우리가 지어내는 것이다. `readPeriodLabel()` 이 기간이 달 경계에 정확히 맞을 때만 `2026년 7월 – 9월` 로 접는다 — **덜 말하는 쪽으로만 틀린다.**
- **끝난 행사는 조용히 빠진다.** 「종료된 행사입니다」 카드를 남기지 않는다. 행사가 전부 끝나는 11월 말~1월에는 구획째 사라지고 `article`·`guide`·`trend` 가 화면을 채운다(§6-3).

**화면 규격.**

| 항목 | 확정 |
|---|---|
| 칩 | **13종 통제 어휘**를 세 줄로(결 5 · 계절 4 · 자리 4). 어휘 원본은 `db/seed/schemas.ts`, 화면 사본은 `src/components/reads/tags.ts` — 값이 한국어 라벨 그 자체라 두 벌이 어긋나면 칩이 조용히 0건이 된다(`tests/reads/schema.test.ts` 가 맞대어 본다). 생김새는 §1.6b 그대로(h44 · 선택 = `--cta-bg` 채움) |

**갱신.** 즉시성은 없다 — PR 이 병합되고 재배포돼야 화면이 바뀌고, 축제 일정은 분 단위로 바뀌지 않으므로 그것으로 충분하다. 주간 점검 지침(만료 청소 · 링크 생존 · 대기 목록 · 계절 보충 · §3-4 규범 훑기)은 조사 문서 §7-3 이 원본이다. ⚠ **크롤러를 만들지 마라** — 그 루틴은 사람이 링크를 열어 보는 일이고, 그게 §1 의 원칙이다.

### 1.5r 도감의 마지막 걸음 — 「사러 가기」와 계절 달력 (2026-08-18)

도감으로 **곧장** 들어온 사람(추천 플로우를 거치지 않은 사람)에게 이 서비스는 두 곳이 막혀 있었다. 상세를 다 읽고 나면 남는 질문이 "그래서 이건 어디서 사지"인데 그 답이 결과 화면에만 있었고, 반대로 꽃 이름을 하나도 모르는 사람에게는 도감에 들어갈 손잡이가 없었다(이름으로 찾거나 생일을 알아야 했다). 이 절이 그 둘을 잇는다.

**① 도감 상세의 「사러 가기」** (`/flowers/[slug]`)

| 항목 | 확정 |

"이번 달엔 어떤 꽃이 필까요"에 답하는 열두 칸. 도감이 **이름**으로, 생일 찾기가 **날짜**로 들어가는 문이라면 여기는 **계절**로 들어가는 문이다.

### 1.5s 결과 화면 세 가지 — 건네주기 · 흘러나오는 멘트 · 적어 준 꽃 (2026-08-18)

세 가지가 한 라운드에서 함께 들어왔다. 서로 다른 기능이지만 규범 하나를 공유한다:
**화면은 자기가 실제로 한 일만 말한다.**

**① 「이 결과 건네주기」 — 저장 0 공유** (`/r?c=…`)

2026-08-17 에 걷어 낸 더미 `링크로 공유` 자리에 실제로 도는 길이 생겨 버튼이 돌아왔다.
그때 지운 근거("눌러도 아무 일 없는 버튼은 갈 곳 없는 링크와 같은 거짓말")가 곧 복귀 조건이었다.

| 항목 | 확정 |
|---|---|
| 방식 | **서버 저장 0.** 링크를 만들 때 아무것도 쓰지 않는다 — 주소에 실린 값만으로 화면을 다시 세운다. 저장하지 않기로 한 것을 공유를 핑계로 저장하지 않는다(§1.5j). 만료·삭제·유출을 걱정할 대상이 애초에 생기지 않는다 |
| 싣는 것 | **3안의 꽃 id · 관계 · 마음 · 날짜**, 넷뿐이다. 전부 우리 어휘이거나 카탈로그 id 라 주소창·리퍼러·남의 채팅방에 남아도 그 사람에 대해 아무것도 말하지 않는다 |
| **싣지 않는 것** | 자유 서술 2필드(수신자 메모·에피소드) · 멘트 본문 · `직접 쓸게요` 한 줄들 · 이름·연락처류 전부. 관계·마음이 `other` 면 **slug `other` 만** 실린다 — 그 한 줄 자체가 자유 서술이다 |
| 부호 | 압축 없는 base64url JSON(`{v,f,r,i,d}`). 실을 것이 id 3개와 어휘 2개뿐이라 압축이 필요 없고, 사람이 눈으로 열어 무엇이 실렸는지 확인할 수 있다 — 무저장 공유에서 그 투명함은 값이 있다. **실측 149자**(운영 도메인 가정 시에도 250자 안, 테스트가 카탈로그 전종 최악 조합으로 잰다) |
| 주소 모양 | **경로가 아니라 쿼리다**(`/r?c=…`). `/r/[code]` 는 정적 드롭 데모에서 **존재할 수 없다** — 동적 세그먼트는 빌드 때 미리 뽑은 경로만 파일이 되는데 부호는 사용자가 그때 만든다. 쿼리는 정적 호스팅이 지나가므로 파일 하나(`/r`)로 모든 부호가 열린다. 배포 방식에 따라 링크가 달라지면 이미 건네준 링크가 다음 배포에서 깨지므로 본배포도 같은 주소를 쓴다 |
| 검증 | 두 걸음이다. ① 모양·어휘(zod — 관계 7종·마음 8종·id 모양·날짜 모양) ② **꽃이 실재하는지**(카탈로그 대조). 하나라도 어긋나면 안내 화면이고, 셋 중 둘만 찾아도 **반쪽을 보여 주지 않는다** — "셋 중 둘"은 건넨 사람의 결과가 아니다 |
| 공유 화면 | **읽기 전용.** 3안의 사진·이름·꽃말·이야기 훅 + 「이런 마음으로 골랐대요」 칩 + 「나도 골라 보기」 CTA. 색 고르기·이야기 시트·멘트·구매가 없다 — 건넨 사람이 아직 고르는 중인 값(색·톤)을 남이 확정된 것처럼 보게 하지 않는다 |
| 정직 한 줄 | 맨 아래 — `이 링크에는 고른 꽃과 관계·마음만 담겨 있어요. 적어 주신 이야기나 멘트는 담기지 않아요.` 없으면 받는 사람은 보낸 사람이 적은 이야기까지 이 주소에 들어 있다고 여긴다 |
| 버튼 | §1.6b **고스트**. 주 버튼은 여전히 「사러 가기」 하나다. 폰이면 기본 공유 시트를 먼저 열고, 없거나 사용자가 **닫으면**(`AbortError`) 아무 피드백도 세우지 않는다 — 취소를 성공처럼 말하지 않는다 |
| OG | **손대지 않는다.** 배포 도메인이 없어 `SITE_URL` 이 `localhost` 로 굳어 있고(§`src/lib/site.ts`), 잘못된 절대 주소는 없는 것보다 나쁘다. `robots: noindex` — 한 사람에게 건넨 링크가 검색에 뜰 이유가 없다 |

**② 멘트 스트리밍 — 결과가 멘트를 기다리지 않는다**

신고: "멘트가 2.4~3.1초 뒤에 한꺼번에 나타난다." 원인은 구조였다 — 제출 액션이 LLM 이
끝나야 반환하므로 그동안 화면이 아무것도 못 세웠다.

| 항목 | 확정 |
|---|---|
| 자리 | **라우트 핸들러**(`POST /recommend/stream`, NDJSON). 서버 액션의 반환값은 한 번에 건너가는 값이라 "조금씩"이 성립하지 않는다. 줄은 넷: `result`(멘트를 뺀 결과 — 먼저 간다) · `draft`(흘러나오는 글자) · `tones`(검증 통과) · `settled`(새로 쓴 문장 없음) |
| 실측 | 결과 화면 **+1.2초**, 멘트 확정 +3.3초. 그 사이 2.1초가 예전에는 빈 화면이었고 지금은 글자가 흐른다(40자 → 107자 관측) |
| 경계 | **`draft` 는 절대 `ToneView.body` 가 되지 않는다.** 복사·고쳐 쓰기·새로 받기가 그 글자를 만지지 못하고, 확정은 스트림 끝에서 계약(zod)을 통과한 값으로만 일어난다. 흘러들어오는 동안 도구줄은 서지 않는다 |
| 폴백 | **체인은 손대지 않았다**(gemini→claude→clova→nvidia, 재시도 규칙 포함). 스트리밍이 가능한 셋만 흘려보내고 CLOVA 는 지금처럼 한 번에 온다(SSE 프레이밍이 다르고 실키로 확인하지 못했다 — 확인 못 한 경로를 켜 두지 않는다) |
| 예문 각주 | 흘러들어오는 동안 **세우지 않는다.** "미리 적어 둔 예문이에요"가 서 있다가 1초 뒤 방금 쓴 멘트로 바뀌면 그 각주가 거짓이 된다. 쓰는 중인 칸에는 예문도 세우지 않는다 — 아직 못 쓴 것은 못 썼다고 말한다 |
| 낭독 | 흘러가는 글자를 live 영역에 두지 않는다(글자마다 읽어 주면 아무것도 알아들을 수 없다). `aria-busy` + 상태 한 줄로 갈음하고, 본문은 확정된 뒤에 읽힌다 |
| 순서 | 톤은 **이름으로 짝짓는다**(도착 순서를 가정하지 않는다). 폴백으로 다른 모델이 다시 쓰기 시작해도 같은 규칙이다 |
| 정적 데모 | 라우트가 **없다**(Next 는 export 빌드에서 POST 라우트를 산출물에 넣지 않는다). 화면은 그 사실을 알고 애초에 부르지 않는다. ⚠ `export const dynamic = 'force-dynamic'` 를 붙이면 `build:static` 이 그 자리에서 죽는다 — 붙이지 마라(실측) |

**③ 멘트 분량 상한** — 사용자 요구 "너무 길지 않게".

- 상한은 **짧게 60자 · 보통 120자**(공백 포함). 관측을 굳힌 값이지 새로 조인 값이 아니다(실측: 짧게 54~61 · 보통 91~110).
- 수치는 **계약 옆 한 곳**에 산다(`MESSAGE_LENGTH_MAX_CHARS`). 프롬프트가 그 수를 요구하고, 응답 검증이 그 수로 막고, 화면의 길이 칸이 그 수를 말한다 — 셋이 각자 숫자를 들면 어느 하나만 늘어난 채 남는다.
- **넘긴 멘트는 잘라 쓰지 않는다.** 중간에서 끊긴 문장은 긴 문장보다 나쁘다. 계약 위반으로 다뤄 같은 프로바이더에 한 번 더, 그래도 넘치면 다음 프로바이더로 — 잘라 붙이는 코드는 어디에도 없다.
- 고쳐 쓰기의 200자는 **별개**다. 우리가 쓰는 분량과 사용자가 고쳐 쓸 수 있는 분량은 다른 약속이다.
- 개정 후 실측(토글별 5회): 짧게 34~52자 · 보통 67~119자. 상한 초과 0.

**④ 「이야기 속 꽃」 정직 한 줄**

실측된 한계: 규칙이 촘촘한 자리(고백 × 연인)에서는 에피소드에 꽃 이름을 직접 적어도
I·R 가점이 그 이름을 이겨 3안에 못 든다. **점수를 비틀지 않고 화면이 이유를 말한다.**

- 엔진은 `mentionedFlowerIds()` **한 줄만** 연다(판정은 `readCues` 가 이미 하던 것 그대로 — 점수식·사전·가중치 불변).
- 세 갈래: 3안 **안** → 아무것도 안 붙는다 / **제외**됨(반려동물·예산·향) → 안 붙는다(그 사정은 제외 쪽의 말이고, 안전 때문에 뺀 꽃을 "덜 가까워서"로 덮어 말하는 것은 §1.5h 위반) / **3안 밖 + 제외 아님** → 한 줄이 선다.
- 문구: `적어 주신 {꽃}도 살펴봤어요 — 지금 고른 셋이 이 마음에 더 가까워서 함께 세우진 않았어요.` 꽃 이름은 도감 상세로 링크. **사과하지 않는다** — 실수가 아니라 판단이다.
- ⚠ **에피소드 원문을 되비추지 않는다.** 담기는 것은 꽃 이름과 도감 id 뿐이다(§1.5j).

**⑤ 정적 데모는 "안 깨짐"이 아니라 "실동작"이다** (사용자 확정)

`templates.csv` 는 (마음 × 톤) 조합마다 행이 하나뿐이라 데모에서는 길이 토글도 새로 받기도
세울 수 없었다. 그래서 **데모 전용 예문 변주 한 벌**을 손으로 썼다(31조합 × 짧게 2벌 +
보통 1벌 = 93문장, `src/lib/demo/message-variants.ts`).

- ⚠ **원장(`templates.csv`)은 건드리지 않는다.** 데모를 위해 원장에 행을 늘리면 본배포의 예문 폴백이 함께 바뀐다.
- 짧은 벌은 **줄여 쓴 것이 아니라 다시 쓴 것**이다(앞부분을 자른 문장은 긴 문장보다 나쁘다). 분량은 생성 경로와 같은 띠(40~60 · 80~120)라 데모에서 토글을 눌러 본 사람이 본배포에서 다른 분량을 만나지 않는다.
- 회전은 **결정적**이다(난수 없음). 짧게는 두 벌을 오가고, 보통은 원장 ↔ 손으로 쓴 한 벌을 오간다.
- 버튼을 세우는 조건은 `ResultPayload.canReword` 하나이고 **데모만 켠다**. 금지선은 그대로다 — 금지된 것은 "눌러도 아무 일 없는 버튼"이지 버튼 자체가 아니다.
- 톤의 `source` 는 계속 `template` 이다 — 데모에서 "당신의 이야기를 담아 썼어요" 배지가 서면 그건 거짓말이다.

### 1.5t 결과 화면 두 가지 — 예시 상품과 「이어지는 읽을거리」 (2026-08-18)

둘 다 **비어 있던 칸을 채우는 일**이고, 규범 하나를 공유한다: §1.5s 가 세운
「화면은 자기가 실제로 한 일만 말한다」. 하나는 지어낸 값을 세우면서 지어냈다고 말하고,
다른 하나는 실제 원장을 세우되 없는 꽃에는 아무것도 세우지 않는다.

**① 「사러 가기」 예시 상품 — 데모 전용** (사용자 확정: "zip 은 모든 기능이 작동하는 것처럼")

시트의 상품 목록 자리가 **본배포에서도 데모에서도 늘 비어 있었다.** 실상품 공급원이 지금 한 곳도 없기 때문이다 — 네이버 쇼핑 API 2026-08-01 종료 · 11번가는 셀러 전용으로 전환 · 쿠팡 파트너스는 수수료 링크라 「제휴 아님」 고지와 충돌(`.env.example` 에 기록). 데모를 보는 사람에게는 그 기능이 아예 없는 것으로 읽혔다.

| 항목 | 확정 |
|---|---|
| 어디서 서는가 | **데모에서만**(`src/lib/demo/sample-products.ts` → `lib/demo/recommend-actions.ts`). 본배포 액션에는 이 파일을 부르는 줄이 한 곳도 없다 — 실서비스에 지어낸 상품은 안 된다. 키가 없으면 그쪽은 지금처럼 `{ ok: false }` 이고 화면은 사이트 목록으로 내려간다. `tests/flow/sample-products.test.ts` 가 소스로 잡는다 |
| 표식 | 응답에 **`sample: true`** 가 실린다(`BuyProductsResponse`). 그 한 칸이 화면 계약이다 — 켜져 있으면 화면은 ① 목록 **위에** 예시 고지를 세우고 ② 행이 상품 상세가 아니라 판매처로 간다고 미리 말한다. 각주로 미루지 않는 이유: 값을 다 읽은 뒤에 알게 되면 이미 진짜로 읽힌 뒤다 |
| 목적지 | **개별 상품이 아니라 그 판매처.** 주소는 지어내지 않고 `buy-links.ts`(실측 원본)에서 그대로 가져온다. 존재하지 않는 상품 상세로 사람을 보내지 않는 것이 이 기능의 첫 조건이다 |
| 값 | 표가 아니라 **결정적 생성기**다(이름 해시 → 4~6줄). 도감이 계속 자라므로(하루에 47 → 59) 손으로 적은 표는 꽃이 늘 때마다 조용히 빈칸을 만든다. 난수는 쓰지 않는다 — 같은 꽃은 언제나 같은 목록이어야 시연과 스크린샷 검수가 되풀이된다 |
| 판매처 | 다섯 곳(우체국 꽃배달 · 카카오톡 선물하기 · 우리화원 · 꾸까 · 플립플라워 스토어). 그중 **셋이 추천순 가산 대상**이 되게 골랐다 — 전부 가산이거나 전부 아니면 추천순 칩을 눌러도 목록이 그대로여서 죽은 버튼이 된다(P2-11) |
| 문구 | 상품명에 **재고·배송·최저가를 약속하는 낱말 금지**(`당일`·`직송`·`최저가`…). 예시라고 적어 두더라도 그것은 우리가 하지 않은 약속이고, 시트 아래 두 줄과 정면으로 어긋난다 |

**② 「이 꽃과 이어지는 읽을거리」 — 결과 화면 ↔ `/reads` 의 다리**

원장 `content/reads.csv` 의 `links_to`(`flower:{id}`)는 읽을거리 쪽에서 꽃을 가리킨다. 결과 화면은 그 화살표를 **거꾸로** 탄다.

| 항목 | 확정 |
|---|---|
| 자리 | **문학 바로 아래, 사러 가기 위.** §1.5r 이 세운 "읽을 것이 다 끝난 뒤 마지막 걸음이 사러 가기" 순서를 지키면서 곁들임끼리 모여 선다 |
| 조회 | `src/lib/data/reads-links.ts` 의 `readsForFlower` — **순수 함수**다. ⚠ `reads-festivals.ts` 안에 두지 마라: 그 파일은 `node:fs` 를 쓰는 서버 전용이고, 부르는 쪽(`build-result.ts`)은 정적 데모에서 **브라우저 번들에 들어간다.** 한 줄만 잘못 가져와도 `build:static` 이 죽고, 그 사실은 몇 분짜리 빌드 끝에야 드러난다(`tests/data/reads-links.test.ts` 가 import 목록으로 1초 만에 잡는다) |
| 무게 | 서버가 **한 안에 최대 세 장**만 싣고 화면은 **두 장**을 세운다. 원장 54건을 통째로 내려보내지 않는다(3안이면 그 무게가 세 배다). 한 장의 여유는 만료로 빠질 자리의 대타다 |
| 만료 | **브라우저의 오늘**로 거른다 — 날짜는 원본 문자열 그대로 건너가고 판정은 `components/reads/expiry.ts` **한 함수**를 쓴다(`/reads` 와 같은 자). 서버가 거르면 배포한 날이 정적 HTML 에 굳는다(§1.5q · §7-2) |
| 머리 한 줄 | **지금 서 있는 카드로** 정한다. 행사가 남아 있으면 `이 꽃이 주인공인 축제가 있어요`, 다 끝나 글만 남으면 `이 꽃과 이어지는 읽을거리가 있어요`. 정직 각주의 「행사 일정 확인」 문장도 같은 조건에서만 붙는다 |
| 없는 꽃 | **아무것도 붙지 않는다**(59종 중 25종만 이어져 있다). 「아직 이어진 글이 없어요」 같은 빈 구획을 세우지 않는다 — 문학 블록과 같은 규칙 |
| 카드 한 장 | 제목 · (행사면) 기간·지역 · 우리가 쓴 한 줄 · 출처. **갈래 칩도 이미지도 없다** — 두 장짜리 곁들임에 칩을 세 겹 세우면 본문을 이긴다. 목록으로 가는 길은 아래 `읽을거리 더 보기` 한 줄이다 |
| 데모 쌍둥이 | 번들 생성기가 `reads` 를 **도감을 가리키는 24행만** 싣는다(`scripts/build-demo-catalog.mjs`). 통째로 비우면 데모에서만 이 구획이 사라지고, 54건을 다 실으면 어떤 꽃도 가리키지 않는 30건이 헛짐이 된다. 목록 화면의 근거인 전 54건은 `reads.ts` 사이드카가 그대로 들고 있다 |

**감사**: 두 기능과 전 라우트 클릭스루 결과는 `docs/demo-audit-2026-08-18.md`.

### 1.5u 카드 미리보기 액자 — `/reads` · `/stories` (2026-08-18)

사용자 요구는 한 줄이었다: "읽을거리의 경우 미리보기 이미지가 있으면 좋겠어. 이야기나 도감 역시 그렇고! **글만 있으니까 보기 좀 까다로워서.**" 그래서 두 활자 화면에 그림을 한 칸씩 들였다. 규범은 하나다 — **우리가 가진 자산만 건다.** 남의 썸네일·기사 사진 핫링크 금지(§1.5q)는 그대로고, TourAPI 축제 이미지도 쓰지 않는다(공공누리 제3유형은 변경 금지라 리사이즈조차 못 한다).

**어떤 자산을 어디에 — 재고 골랐다(2026-08-18 실측).**

| 자리 | 고른 것 | 근거 |
|---|---|---|
| `/reads` 카드 | **도판 160px 썸네일**(`public/plates/thumbs/`) | 자체 호스팅이라 **외부 요청 0**, 장당 평균 7.8KB(최대 13KB) → 24장 전부 190KB. 실사는 허용된 가장 좁은 폭이 640px 이라 장당 50~80KB에 외부 요청이 24개 늘고, 47/59 종만 있어 빠지는 카드가 생긴다. 값이 열 배 싸고 빠짐이 없으며, 다크 배경 위 세밀화 액자가 이 서비스의 시그니처다 |
| `/stories` 레인 카드 | **대표 실사 1컷**(`photosFor()[0]`) | 레인 헤더에 이미 도판이 44px 로 서 있다 — 카드까지 같은 그림이면 한 줄에 같은 그림이 아홉 번 선다. 판면(종이)과 얼굴(사진)로 결을 갈랐다. 컷이 없는 꽃은 도판으로 되돌아가지만 **지금은 한 줄도 그 갈래를 타지 않는다**(59종 전원에 컷이 있다) — 사진이 카탈로그보다 늦는 날을 위한 폴백이다 |

**액자 문법은 한 벌이다.** `/reads` 에서 도감과 이어지지 않은 카드(54건 중 30건)에 **빈 회색 상자를 두지 않는다.** 같은 크기·같은 골드 헤어라인의 액자에 갈래 선화 넷(핀·펼친 책·물방울·색 스와치)이 들어간다. 두 갈래가 밝고(아이보리 판면) 어둡게(골드 12% 틴트) 갈리는 것은 의도다 — 그 차이가 곧 "이 글은 우리 도감의 꽃과 이어져 있다"는 사실이고, 그 말은 카드 아래 다리 링크가 이미 하고 있다. ⚠ 도판 크롭을 갈래 대표로 재사용하지 마라 — 그 순간 「이 글이 그 꽃 이야기다」라는 거짓말이 된다.

| 항목 | 확정 |
|---|---|
| 크기 | `/reads` 64px × 3:4 세로(판면이 세로다) · `/stories` 60×60 정사각(장면컷은 세로로 자르면 배경만 남는다). **CSS 가 상자를 먼저 세운다** — `aspect-ratio`/고정 px 이라 그림이 늦어도 줄이 밀리지 않는다 |
| 폭 | 도판은 `plateSrc(plate, 250)` = 썸네일. 실사는 `photoSrc(photo, 640)` — 폭 치환 표(`PHOTO_SOURCES`) **밖의 임의 폭 금지**. 640 은 표가 허용하는 가장 좁은 값이고 도감 카드·달력 칩·사전 썸네일이 이미 쓰므로 **받아 둔 사본이 재사용된다** |
| 요청 수 | 한 레인의 카드 여덟 장은 **같은 주소 한 벌**을 문다 → 늘어나는 요청은 레인당 하나. 전부 `loading="lazy"` 이고 레인 지연 렌더는 그대로다 |
| 낭독 | **장식이다**(`aria-hidden`). 꽃 이름은 카드가 텍스트로 이미 말하고 갈래는 첫 줄 라벨이 말한다 — 54장·472장에서 두 번 읽으면 소음이다(레인 헤더 도판과 같은 판단) |
| 경계 | 클라이언트 컴포넌트는 `@/lib/plates` · `@/lib/photos` 를 **값으로 import 하지 않는다**(코드 리뷰 P1-7). 서버가 주소만 좁혀 props 로 내려보낸다 — `ReadCard.preview` · `ArchiveLane.shotSrc` |
| 크레딧 | 그림이 서면 그 화면이 표기를 진다. `/reads` 푸터에 **도판 크레딧**(판본 단위, `/stories` 와 같은 형식), `/stories` 푸터에 **사진 크레딧**을 `<details>` 로 접어 추가(작가 단위라 마흔 줄이 넘는다 — 결과 화면·도감 갤러리와 같은 문법) |

**`--lane-h` 를 다시 쟀다.** 레인 자리표시 높이는 카드가 커진 만큼 따라가야 한다(부족하면 CLS, 남으면 카드가 줄 위쪽에 뜬다). 23개 폭에서 카드 359장을 전부 세우고 잰 값:

| 구간 | 320~ | 360~ | 640~ | 768~ | 1040~ | 1280~ |
|---|---|---|---|---|---|---|
| 전 | 363 | 363 | 363 | 337 | 363 | 363 |
| 후 | **397** | **397** | **397** | **371** | **397** | **397** |

여섯 구간 중 다섯이 한 값으로 모였다 — 60px 액자가 첫 줄 높이의 **바닥**이 되면서 결 칩이 한 줄이냐 두 줄이냐로 갈리던 ±5px 흔들림이 액자 안에 흡수됐다. 그래서 CSS 사다리는 세 칸으로 접혔다. ⚠ 카드 글자·줄 수나 액자 크기를 건드리면 **여섯 구간을 전부 다시 재라.**

**곁다리 하나 — 320px 가로 넘침.** `/reads` 카드 그리드의 최소 트랙이 `300px` 고정이라 276px 짜리 `.wrap` 안에서 카드가 322px 에서 끝나고 있었다(뷰포트 320px). `html { overflow-x: clip }` 이 스크롤바를 가려 눈에 덜 띄었을 뿐 오른쪽 24px 이 잘려 나갔다. `minmax(min(300px, 100%), 1fr)` 로 막았다 — 344px 이상에서는 계산 결과가 그대로다.

**실측(프로덕션 빌드 · 320/390/768/1280).** 두 화면 모두 `documentElement.scrollWidth == clientWidth` 이고 `body.scrollWidth` 도 같다(**가로 넘침 0**). 이미지 깨짐 0, 콘솔 0. CLS 는 `/stories` 0.0004~0.0009(전과 같음), `/reads` 320·390 ≈ 0 · 768 0.0042. `/reads` 1280 에서 간헐적으로 0.038~0.062 가 뜨는데 **액자를 끈 대조 빌드에서 같은 값·같은 출처로 재현된다** — `<main>` 위쪽(인트로 `.sub`, `max-width: 46ch`)이 웹폰트 스왑에 한 줄 늘었다 줄어드는 기존 현상이라 이 라운드의 회귀가 아니다.

### 1.5v 다발 짜기 — `/bouquet` (2026-08-18)

§1.5i가 로드맵에 올려 둔 **꽃말 조합기**를 실제 화면으로 세운 라운드다. 다만 그때 적어 둔 모습("꽃 2~4종을 고르면 각 꽃말을 한 문장으로 **결합**")과는 한 가지가 다르다 — **문장을 합성하지 않는다.** 두 꽃말을 이어 붙여 "미안하다는 말에 그치지 않고, 다시 다정하게 시작하고 싶어" 같은 한 문장을 만들면 그 문장은 어느 출처에도 없는 우리 창작이 되고, 출처를 달 수도 없다. 그래서 이 화면은 꽃말을 **나란히 놓고** 그 차이를 짚는 데서 멈춘다. 그 대신 로드맵이 함께 적어 둔 「단체 부케와 연계」는 지켰다 — 안전 판정이 `/groups`와 같은 함수를 부른다.

도감이 "이 꽃은 무엇인가"를 말하는 자리라면 여기는 **"이 꽃들을 함께 두면 어떤가"**를 말하는 자리다.

**조합의 크기 — 주 꽃 1 + 곁들이 0~2 = 최대 3종.** 이 3은 단체 부케의 `MAX_BOUQUET_FLOWERS`와 **같은 수**다(두 화면이 같은 "한 다발"을 말한다). 상수를 서로 import 하지는 않는다 — `group.ts`가 zod를 끌고 오는데 이 판정은 브라우저에서 돌기 때문이다. 대신 `tests/engine/bouquet.test.ts`가 `1 + MAX_ACCENTS === MAX_BOUQUET_FLOWERS`를 맞대어 본다.

**곁들이 6종은 우리가 고른 목록이다.** `flowers.csv`에 「곁들이」 컬럼은 없다. 유칼립투스·안개꽃·스타티스(주인공으로 서는 일이 거의 없는 세 종) + 목화(마른 소재) + 수레국화·스카비오사(작은 들꽃 결 — 마침 `pet_safety.csv`가 유칼립투스·목화의 안전 대체로 지목한 종들이다). 지어낸 꽃은 하나도 없고 전부 카탈로그 59종 안이다. ⚠ 목록을 늘리려거든 id를 더하기 전에 `flowers.csv`에 컬럼을 만드는 쪽을 먼저 보라 — 길어질수록 "우리가 고른 것"이라는 사실이 코드 안에 숨는다(기술부채 기록). 주 꽃 목록은 **59종 전부**이고, 곁들이 결이 특히 강한 세 종만 뒤로 민다(빼지는 않는다 — 뺄 근거가 데이터에 없다).

**판정 카드가 말할 수 있는 것 넷.** 그리고 그 넷 **밖의 말은 하지 않는다.**

| 갈래 | 근거 데이터 | 말하는 것 | 말하지 않는 것 |
|---|---|---|---|
| **안전** | `pet_safety.csv` → `exclude()` | §1.5h 직설 한 줄(`이 조합은 고양이가 있는 집엔 어려워요 — 유칼립투스 때문이에요`) + `safe_alternative_flower_ids`가 지목한 대체 + **판정 출처 링크** | 완곡한 표현. `mild_gi`는 빼지 않고 `<details>`로 접어 둔다(§1.5h "상세는 접힘/툴팁") |
| **색** | `flowers.csv` `colors` 교집합 · `aesthetic_tags` 5축 교집합 · `meanings.csv` | 같은 색을 낼 수 있는가 · 결이 겹치는가 · **같은 색인데 품는 말이 다르면 두 꽃말을 나란히** | 보색·유사색 등 **색 이론**. 궁합 점수·별점 |
| **향** | `flowers.csv` `fragrance_level` 합 | 진한 꽃(>=2)이 몇인가 · 자리를 피하라는 한 줄 | 향의 계열·조향 용어 |
| **꽃말** | `meanings.csv`(색별) | 담긴 꽃이 그 색으로 품는 말 + 신뢰 등급 라벨 | 여러 꽃말을 **한 문장으로 합성**하기 |

- **문턱을 새로 만들지 않는다.** 「위험」은 `exclude()`의 `EX_PET_TOXIC`(serious 이상), 「향이 진하다」는 같은 파일의 `EX_FRAGRANCE`(`fragrance_level >= 2`)와 **같은 값**이다. 같은 꽃을 한 화면에서는 "향이 진해요"라 하고 다른 화면에서는 후보로 세우면 두 화면이 서로를 부정한다. 두 문턱 다 카탈로그 59종 전수로 맞대어 본다.
- **말할 것이 없으면 없다고 적는다.** 색도 결도 겹치지 않는 조합에는 `이 조합에 대해 저희 데이터가 말해 주는 건 없어요 — 색 궁합을 점수로 지어내지는 않을게요. 눈으로 골라 주세요.` 가 선다. ⚠ 이 문장을 "더 나은 카피"로 바꾸지 마라 — 이 자리를 그럴듯한 말로 메우는 순간 화면 전체가 점집이 된다. 테스트가 이 문장을 잠근다.
- **미리보기는 색 점 + 세밀화 썸네일뿐이다.** 사진을 합성하지 않는다(없는 다발을 지어내면 그 순간 상품 페이지가 된다). 곁들이의 색은 **주 꽃이 입은 색을 낼 수 있으면 그 색**, 아니면 그 꽃의 대표색이다.

**서버 액션이 하나도 없다.** 조합은 사용자가 화면에서 바꾸고 판정은 그때마다 브라우저가 다시 계산한다 — 정적 드롭 데모(`out/`)와 본배포가 **글자 한 자까지 같은 화면**이다. 대신 카탈로그 59종을 서버가 한 번에 좁혀 props로 내려보낸다(실측 **87.2KB / gzip 11.5KB**, `/bouquet` HTML 152KB — `/reads` 163KB · `/stories` 422KB와 같은 급). 싣는 것은 엔진 `FlowerData` + 색당 꽃말 **한 줄**(369행이 아니라 279칸) + 안전 대체(이름까지 풀어서) + 48px 썸네일 주소다. ⚠ 여기에 서버 액션·`fetch`를 들이지 마라 — `output: 'export'` 빌드가 깨지거나 정적 zip에서 판정이 죽는다(`tests/components/bouquet-screen.test.ts`가 소스에서 잡는다).

**공유는 이번에 넣지 않았다.** 조합을 URL로 되살리려면 공유 부호 스키마가 있어야 하는데 그 스키마가 아직 없다 — 후속.

**진입점.** 지금은 `/sitemap.xml` 한 줄과 직접 주소뿐이다. 화면 안에서 밖으로 나가는 길(`/recommend`·`/flowers`·`/groups`)은 세워 두었지만 **밖에서 들어오는 길은 아직 없다** — 이 라운드에서 랜딩 푸터와 `/flowers` 인트로가 다른 작업자 소유라 손대지 못했다. 홈 푸터 보조 메뉴 한 줄 + `/flowers` 인트로 한 줄이 남은 일이다.

**실측(정적 `out/` · 프로덕션 `next start` 각 3회).** 390/768/1280 전부 `documentElement.scrollWidth == innerWidth`(**가로 넘침 0**), 콘솔 오류 0, 페이지 오류 0. 전 흐름(주 꽃 → 곁들이 → 색 → 판정 → 사러 가기 시트)이 정적 산출물에서도 서버에서도 같게 돈다. `<Link>` 프리페치의 `ERR_ABORTED`는 정적 export를 평범한 파일 서버에 올리면 **모든 화면에서** 나는 소음이다(대조 실측: `/reads` 1건 · `/stories` 1건 · `/flowers` 6건 · `/groups` 2건 · `/bouquet` 1건).

### 1.6b 버튼·칩 통합 시스템 (2026-08-15 사용자 17차 — "버튼·필터 UI 일관성")

전 화면(랜딩·플로우·결과·/stories·/groups)의 인터랙티브 컨트롤을 아래 단일 규격으로 통일한다. 각 영역 모듈 CSS에서 팔레트 변수로 구현(값 하드코딩 금지):

| 컨트롤 | 규격 |
|---|---|

### 1.6c 모바일 내비 메뉴 (2026-08-17 A안 확정 — 조용한 헤더)

860px 아래에서는 데스크톱 링크 다섯 개를 접고 **워드마크 왼쪽 + `메뉴` 오른쪽**만 남긴다. 이전의 `워드마크 + 추천 시작 + 메뉴` 조합은 한 유리 면 안에 알약이 세 겹으로 보여 작은 화면에서 내비보다 툴바처럼 읽혔고, 바로 아래 히어로의 추천 CTA와 역할도 중복됐다. 선택한 A안은 색·유리·타이포·버튼 규격을 그대로 쓰되 상단의 역할을 브랜드와 탐색으로 좁힌다. 비교 시안은 `design/mobile-header-options/index.html`에 보존한다.

- **항목은 다섯**: `오늘의 꽃`(#db-today) · `이야기` · `읽을거리`(/reads) · `도감` · `편지`. 데스크톱의 `시작하기` 대신 시트의 주 CTA가 바로 추천 플로우로 보낸다
  - ⚠ 원안의 다섯째는 `여러 명에게`(/groups)였으나 **2026-08-17 사용자 확정으로 시트에서도 뺐다**("추천받기가 있으니까"). 그 자리는 2026-08-18 에 「읽을거리」가 채웠다 — 페이지 수가 아니라 **본류의 목차**라는 성격은 그대로다. 다시 늘릴 때는 860px 레일 폭을 먼저 재라(861px 실측: 레일 556px · 여유 있음)
- 상단 구조는 `<header>` 배너 랜드마크 안의 `<nav aria-label="주요 메뉴">`다. 시트는 유리 내비의 `overflow:hidden`과 고정 위치 컨테이닝 블록에 갇히지 않도록 **header·nav 밖**에 둔다
- 닫혀 있으면 시트는 DOM에 없다. 열리면 `role="dialog"` + `aria-modal="true"`, 즉시 포커스 이동, Tab 순환, Esc·배경·닫기 버튼으로 닫기, 닫은 뒤 여는 버튼으로 포커스 복귀를 유지한다
- 열려 있는 동안 **header·main·footer 셋 다 `inert`**다. 포커스 복귀는 `inert`가 풀린 뒤 이펙트에서 실행한다
- 배경 탭은 `closest('a, button')`으로 가른다. 목차의 번호와 행 여백도 링크 안에 있으므로 항목을 누르려다 시트만 닫히는 구간이 없다
- 스크롤 잠금은 게이트와 공유하는 셈 방식 `body-scroll-lock.ts` 한 벌을 쓰며, 해제 함수는 멱등이다
- 순차 등장 `opacity:0`은 `prefers-reduced-motion:no-preference` 안에만 둔다. 모션을 줄인 사용자에게는 시트가 즉시 완전히 보인다
- 회귀 방어: `tests/components/landing-mobile-nav.test.ts`가 모바일 CTA 제거·풀폭 레일·320px 라벨·safe-area·행 전체 타깃·5개 목적지·대화상자·`inert`·잠금·reduced-motion을 검사한다

### 1.6 접근성·품질 공통 규칙

- 본문 대비 4.5:1↑, 최소 폰트 14px, 터치 타깃 44×44px↑.
- SVG 비주얼: `role="img"`+`aria-label`(예: "흰 튤립 일러스트"), 장식용 `aria-hidden="true"`.
- 탭: `role="tablist"/"tab"/"tabpanel"`, `aria-selected`, `<button>` 사용.
- 진행 표시 `aria-label="5문항 중 1번째"`. 헤딩 h1→h2→h3 순차.

### 1.7 꽃 비주얼(SVG)

분홍 장미·흰 튤립·푸른 히아신스를 인라인 SVG로 단순화해 직접 그린다. 사실적일 필요 없음 — 방향별 스타일에 맞는 추상화. viewBox 정사각(0 0 200 200) 권장, 색은 팔레트·파생 틴트만.
