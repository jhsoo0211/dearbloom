# 파트너 페이지 실존 큐레이션 조사 (2026-08-16)

`/partners` 의 「함께하는 꽃집」 구획에 실을 **실존하는 곳들**을 조사·검증한 기록이다.
이 문서는 페이지에 실린 모든 항목의 **근거 원장**이다 — 페이지를 고칠 때 여기부터 고친다.

## 왜 바꿨나

이전 `/partners` 는 가상 상호 3곳(`밤의 온실` · `튤립과 편지` · `초저녁 식물상회`)과
`href="#"` 대신 놓아 둔 비활성 버튼으로 채워져 있었다. 예시라고 고지는 했지만,
**갈 수 있는 곳이 하나도 없는 소개 페이지**였다.

사용자 확정 방향(2026-08-16):

> "공공에서 운영하거나 좋은 취지로 하는 꽃집 우선 추천과 링크 연결 + 고속버스터미널 꽃집도"

그래서 가상 예시를 걷어내고, **실존 확인·링크 검증을 마친 곳만** 큐레이션으로 싣는다.

---

## 1. 선정 기준 (명문화)

아래 다섯 가지를 **전부** 만족해야 싣는다. 하나라도 어긋나면 뺀다.

| # | 기준 | 판정 방법 |
|---|------|-----------|
| 1 | **실존** | 운영 주체(법인·기관·조합)의 이름과 소재지가 공식 소스에 적혀 있을 것 |
| 2 | **링크 생존** | 게재할 URL이 HTTP 200 으로 응답하고, TLS 인증서가 **그 도메인의 것**일 것 |
| 3 | **내용 실재** | 그 URL을 열었을 때 **실제 내용**이 나올 것. 로딩 셸(JS 껍데기)만 오는 곳은 뺀다 |
| 4 | **취지 검증 가능** | "좋은 취지"를 **한 줄로 인용 가능한 근거**로 뒷받침할 것 — 그 기관 자신의 문구, 공공기관 안내, 또는 법령·조례. 추측으로 취지를 지어내지 않는다 |
| 5 | **편중 금지** | 특정 상업 꽃배달 업체로 기울지 않을 것. 시장·플랫폼은 **개별 점포가 아니라 시장 자체**를 안내한다 |

#### 기준 #2 를 적용할 때 갈라 봐야 하는 두 가지

둘 다 "인증서 문제" 라고 뭉뚱그리기 쉬운데, **사용자가 겪는 일이 다르다.**

- **도메인 불일치** — 인증서에 적힌 이름이 아예 다른 도메인이다. 모든 브라우저가 경고를 띄운다.
  죽은 링크와 같이 취급해 **뺀다**. → 영남화훼원예농협을 뺀 이유.
- **체인 불완전** — 인증서는 그 도메인 것이 맞는데 서버가 **중간 인증서를 빼먹고** 보낸다.
  크롬·사파리는 AIA 로 알아서 받아와 정상으로 열리고, 파이어폭스는 캐시에 없으면 경고를 띄운다.
  엄격한 클라이언트(Node `fetch` 포함)는 거부한다. → **싣되 경고로 남긴다.** 현재 베어베터 1건.

추가로 지키는 것:

- **비교·비방 금지.** 어느 곳이 더 낫다고 말하지 않는다. 갈래별로 나란히 놓기만 한다.
- **허위 제휴 암시 금지.** 지금은 어느 곳과도 제휴 관계가 아니다. 페이지에 그대로 적는다.
- **개별 점포 링크 금지.** 예컨대 양재꽃시장 안 특정 점포 페이지(`.../market/view.do?...`)는
  실재하지만 **한 가게만 띄우는 셈**이라 걸지 않는다. 시장 대문으로 건다.

  ```
  $ echo | openssl s_client -connect www.bearbetter.net:443 -servername www.bearbetter.net
  Certificate chain
   0 s:CN=*.bearbetter.net
     i:C=GB, ..., CN=Sectigo RSA Domain Validation Secure Server CA   ← 이 중간 인증서가 안 온다
  ```

  인증서 자체는 `*.bearbetter.net` 으로 **정확하다**(도메인 불일치가 아니다). 그래서 크롬·사파리는

  Node `fetch` 는 `UNABLE_TO_VERIFY_LEAF_SIGNATURE` 로 거부한다.
  → 기준 #2 해석에 따라 **싣되**, 검증 스크립트가 `⚠` 로 계속 알리게 두었다.
  저쪽이 체인을 고치면 경고는 저절로 사라진다(`KNOWN_CHAIN_GAPS` 에서 지우면 된다).

## 5. 결과 화면이 쓰는 검색 딥링크 (2026-08-17)

사용자 요구: **"실제 해당 꽃을 살 수 있는 곳으로 연결해줘야 해."**
결과 화면(`src/components/flow/ResultView.tsx`)은 추천한 꽃 이름을 알고 있으므로, 그 이름을
검색어로 넘긴다. **후보를 전부 브라우저로 열어 실측한 뒤** 아래 조합을 골랐다.
바꾸기 전에 이 표를 다시 재 보라 — 그럴듯해 보이는 조합이 대부분 거짓말을 한다.

### 채택 ① 우체국 꽃배달 검색 — `search.do?searchTerm={대표이름} 꽃배달`

`https://mall.epost.go.kr/fo/search/search.do?searchTerm=` + `encodeURIComponent('장미 꽃배달')`

| 검색어 | 결과 | 카테고리 |
|--------|------|----------|
| `장미 꽃배달` | 12개 | 꽃배달(12) |
| `카네이션 꽃배달` | 4개 | 꽃배달(4) |
| `국화 꽃배달` | 2개 | 꽃배달(2) |
| `해바라기 꽃배달` | 1개 | 꽃배달(1) |
| `튤립·수국·프리지아·거베라·백합·은방울꽃 꽃배달` | 0개 | 「해당하는 상품이 없습니다」 안내(HTTP 200) |

- **핵심**: 결과가 **전부 꽃배달 칸**이고, 없으면 **정상 안내 페이지**가 뜬다. 둘 다 200이다.
- **⚠ `꽃배달` 을 빼면 안 된다.** 이름만 넣으면 딴것이 나온다(실측):
  `튤립` → 튤립닭발 · `수국` → 수국차 · `프리지아` → 후리지아 비누 · `은방울꽃` → 인센스.
- **⚠ 꽃 칸 안쪽 검색(`flowerSend.do?srchGoodsNm=…`)은 쓰지 마라.** 맞는 상품이 있을 때는
  잘 되지만 **0건이면 `500 Internal` 에러 페이지**가 뜬다(튤립·수국·거베라로 재현).
  빈손으로 돌아오는 것과 고장 난 화면은 사용자에게 전혀 다른 일이다.
- **대표 이름 규칙**: 괄호 속 딴이름과 앞에 붙은 색·품종 수식을 뗀다
  (`빨간 장미` → `장미`, `아시아틱 백합` → `백합`, `미모사(은엽아카시아)` → `미모사`).
  수식을 붙이면 결과가 0이 된다(`빨간 장미 꽃배달` 0건 vs `장미 꽃배달` 12건).
  ⚠ 이름 목록을 코드에 적어 두지 않았다. `content/flowers.csv` 는 계속 자란다 —
  이 조사를 하는 동안에도 47종에서 59종이 됐다. 규칙만 두고 목록은 두지 않는다.

### 채택 ② 네이버 지도 `꽃집` 검색 — `map.naver.com/p/search/꽃집`

| 환경 | 도착지 | 결과 |
|------|--------|------|
| 데스크톱 | `map.naver.com/p/search/꽃집?c=…` | 목록 정상 |
| 모바일 | `m.map.naver.com/search?query=꽃집` 로 자동 전환 | 목록 정상 |

- **왜 카카오맵이 아닌가**: `map.kakao.com/?q=꽃집` 은 데스크톱에서는 잘 되지만(29,020건),
  **모바일에서 `applink.map.kakao.com` 앱 설치 안내로 가로막혀** 목록을 볼 수 없다(실측).
- **⚠ 검색어에 꽃 이름을 붙이지 마라.** 지도는 **가게 이름**을 찾는다.
  `장미 꽃집` → 수원(32km)·대전(143km)·경산(258km)·부산(333km)의 「장미꽃집」이 나온다.
  그 가게에 장미가 있다는 뜻이 **전혀 아니면서** 있는 것처럼 읽힌다 — 이게 제일 나쁜 거짓말이다.
  그래서 이름은 지도 검색어가 아니라 **바로 아래 안내 문구**로 넘긴다("가까운 꽃집에 ‘수국’ 있는지
  물어보세요").

### 기각한 후보

| 후보 | 사유 |
|------|------|
| `map.kakao.com/?q=` | 모바일 앱 설치 벽 |
| `{꽃이름} 꽃집` 지도 검색 | 상호명 매칭 — 수백 km 밖 동명 가게를 끌어온다 |
| `search.do?searchTerm={이름}`(꽃배달 없이) | 닭발·차·비누가 섞여 나온다 |
| `flowerSend.do?srchGoodsNm={이름}` | 0건일 때 500 에러 |
| `search.do?…&pavlnDivCd=04` | `pavlnDivCd` 가 **무시된다** — 칸이 좁혀지지 않는다 |
| e경남몰 검색 `kwa-ABS_goods_l_sch?search_value={이름}` | 200에 빈 결과도 정상이지만, `장미` → 장미식초·장미꽃차·장미 롤케이스가 나온다 |
| 남도장터 `/search?keyword=` | **404** — 그런 경로가 없다 |

### 이 링크들이 지켜야 하는 것

1. **재고·가격·배송을 약속하지 않는다.** 문구는 "여기서 팝니다"가 아니라 "찾아보기" 결이다.
2. **0건이 정상이다.** 그래서 링크 바로 아래 한 줄이 "없으면 가까운 꽃집에 물어보세요"라고 말한다.
   그 줄을 지우면 링크가 재고를 약속하는 말이 된다.
3. **제휴 암시 금지** — 위 4번 항목과 같다.

## 6. 이 목록을 고칠 사람에게

1. **링크가 죽으면 문구를 고치지 말고 항목을 빼라.** 죽은 링크를 남기느니 없는 게 낫다.
2. **취지 근거 없이 항목을 추가하지 마라.** 위 표의 `취지 근거` 칸을 채울 수 없으면 넣지 않는다.
3. **제휴가 실제로 생기면** 페이지의 정직 각주("아직 제휴 관계는 아니에요")를 그때 고친다.
   각주가 사실과 어긋나는 순간 페이지 전체의 신뢰가 같이 무너진다.
4. **개별 점포를 넣고 싶어지면 참아라.** 시장 안 한 가게를 띄우는 순간 기준 #5가 깨진다.
