# 「읽을거리」 섹션 조사 (2026-08-17)

`content/reads.csv` 에 실린 **모든 항목의 근거 원장**이다. 목록을 고칠 때 여기부터 고친다.
파트너 페이지(`docs/partners-research.md`)와 같은 규범을 따른다 — 링크가 죽으면 문구를
고치지 말고 **항목을 뺀다.**

> ⚠ 이 문서는 **화면을 만들 다음 worker 가 읽을 문서**다. §6「만료 항목 거르기」와
> §7「배포와 갱신」이 그 사람을 위한 자리다. 데이터만 보고 화면을 짜면 지난 행사가
> 남는다 — 이 섹션의 최대 위험이 그것이다.

---

## 1. 이 섹션이 무엇이고, 무엇이 아닌가

사용자 요구는 "꽃 관련 아티클이나 새로 올라오는 유명한 내용을 볼 수 있는 섹터",
이어서 "예쁜 꽃이나 올해의 컬러 등 연결시킬 수 있는 부분", 그리고 "꽃 관련 축제 소개 +
재미 + 감성적인 + 카테고리 분류" 였다.

**우리는 크롤링을 하지 않는다.** 그래서 이 섹션은 *사람이 고른 외부 읽을거리를
제목·출처·한 줄 소개·링크로만* 싣는다.

| 한다 | 하지 않는다 |
|---|---|
| 우리가 직접 쓴 한 줄 소개(`summary_ko`) | 기사 본문·요약문 전재 |
| 매체명 + 필자 + 원문 링크 | 본문을 우리 DB에 저장 |
| 유료 장벽 표기(`access`) | 유료 벽을 감추고 링크만 걸기 |
| 우리 도감과 잇는 `links_to` | 억지 연결 |
| 공식 안내에서 확인한 행사 날짜 | 기사·블로그 재인용 날짜 |

### 왜 크롤링을 하지 않기로 했나 (나중에 다시 제안할 사람을 위해)

세 가지 이유가 각각 독립적으로 충분하다.

1. **저작권.** 기사 본문을 긁어 저장·재배포하면 그건 인용이 아니라 복제다. 요약도
   기계가 원문에서 뽑으면 2차적저작물 다툼의 자리에 선다. 우리가 직접 읽고 우리
   문장으로 한 줄 쓰는 것과는 법적 성질이 다르다.
2. **인프라.** 크롤러는 서버·스케줄러·저장소·차단 대응·robots.txt 준수·재시도 큐를
   전부 끌고 온다. 지금 이 서비스는 **정적 배포로 도는 사이트**다(§7). 크롤러 하나
   때문에 상시 서버를 세우는 것은 비용의 방향이 거꾸로다.
3. **신뢰.** 이 서비스의 데이터 원칙은 "출처를 열어 본 것만 싣는다" 다(꽃말·일화·
   탄생화 전부 그렇게 쌓았다). 자동 수집물은 그 원칙을 지킬 수 없다 — 사람이 열어
   보지 않은 링크가 목록에 서는 순간, 죽은 링크와 낚시 제목을 우리가 보증하게 된다.

> 자동화하고 싶은 충동이 생기면 **크롤러가 아니라 주간 리서치 루틴**(§7-3)으로 보낸다.
> 사람(또는 사람이 검토하는 에이전트)이 조사하고 PR 로 올리는 흐름이 우리 원칙과 맞는다.

## 2. 선정 기준

파트너 페이지의 다섯 기준을 이 섹션에 맞게 옮겼다. **전부 만족해야 싣는다.**

| # | 기준 | 판정 방법 |
|---|------|-----------|
| 1 | **링크 생존** | 게재할 URL 이 실제로 열리고, 그 도메인의 정상 인증서를 쓸 것 |
| 2 | **내용 실재** | 그 URL 에 **실제 내용**이 있을 것. 로딩 셸·로그인 벽·소프트 404 는 뺀다 |
| 3 | **출처 실명** | 매체명이 분명하고, 필자가 표기돼 있으면 함께 적을 것 |
| 4 | **오래 읽히는 글** | 시의성보다 수명. 이번 주 뉴스는 다음 달에 죽는다 |
| 5 | **날짜 확인**(행사만) | 시작·종료일을 **주최 측 공식 안내**에서 확인할 것 |
| 6 | **편중 금지** | 한 매체·한 지역·한 나라로 기울지 않을 것 |

추가로 지키는 것:

- **본문을 옮기지 않는다.** `summary_ko` 는 60~90자, 전부 우리가 새로 쓴 문장이다.
- **이미지를 얹지 않는다.** `reads.csv` 에 이미지 URL 칸을 두지 않았다. 매거진 썸네일·
  기사 사진 핫링크 금지, 다운로드 금지. 화면에 그림이 필요하면 **우리가 이미 가진**
  실사(`content/birth_photos.csv`)·도판을 쓴다.
- **브랜드 자산을 복제하지 않는다.** 팬톤 로고·공식 스와치 이미지를 가져오지 않는다.
  색 이름과 공식 코드를 **사실로 적고** 원문을 링크하는 것까지가 우리 몫이다(§4-1 참조).
- **비교·비방 금지, 허위 제휴 암시 금지.** 어느 축제가 더 낫다고 말하지 않는다.

## 3. 스키마

```
read_id,kind,title,source_title,author,source_url,published_at,starts_at,ends_at,
region,summary_ko,access,confidence,reviewed_at,tags,links_to,editorial_note
```

| 컬럼 | 필수 | 뜻 |
|---|---|---|
| `read_id` | **필수** | `read-` 접두 kebab slug. 파일 안에서 유일. |
| `kind` | **필수** | `article` `event` `guide` `trend` 네 값. **데이터의 종류**다. |
| `title` | **필수** | 그 글·행사의 제목. 원문 표기 그대로. |
| `source_title` | **필수** | 매체·기관 이름. |
| `author` | 선택 | 필자·주최. 표기가 없으면 빈칸. |
| `source_url` | **필수** | 원문 링크. 전수 실제 확인(§5). |
| `published_at` | 선택 | 원문에 발행일이 표기된 것만. `YYYY-MM-DD`. |
| `starts_at` / `ends_at` | **`event` 만 필수** | 공식 안내에서 확인한 날짜. 그 외 갈래는 빈칸. |
| `region` | 선택 | 오프라인이면 지역, 온라인/무관이면 `온라인` 또는 빈칸. |
| `summary_ko` | **필수** | **우리가 쓴 한 줄**(60~90자). §1.5d 톤. |
| `access` | **필수** | `open` `paywall` `registration`. |
| `confidence` | **필수** | `repeated` `varies` `single_source` — 기존 CSV 와 같은 어휘. |
| `reviewed_at` | **필수** | 우리가 링크를 열어 본 날. |
| `tags` | **필수** | 화면 칩이 될 통제 어휘. `|` 구분(§3-2). |
| `links_to` | 선택 | 우리 데이터와 잇는 칸. `|` 구분(§3-3). **비는 것이 정상 값**이다. |
| `editorial_note` | 선택 | **화면 비노출.** 채택 근거·주의점·대조 기록. |

### 3-1. `kind` — 데이터의 종류

| 값 | 담는 것 |
|---|---|
| `article` | 꽃·식물·화훼 산업을 다룬 오래 읽히는 글 |
| `event` | 축제·전시·박람회·식물원 특별전. **날짜 필수** |
| `guide` | 절화 관리·꽃 고르는 법 등 실용 정보. **공신력 있는 출처만** |
| `trend` | 올해의 컬러·플로럴 트렌드·매거진 특집·비주얼 기획 |

### 3-2. `tags` — 화면에서 사람이 골라 보는 카테고리 (13개, 확정)

`kind` 가 *데이터의 종류*라면 `tags` 는 *사람이 고르는 축*이다. 축이 다르므로 값도 다르다.
**한글 라벨 그대로 쓴다** — 이 표는 사람이 손으로 채우는 원장이라 코드 slug 를 따로 두지
않는다. 화면 칩에 이 문구를 그대로 건다.

| 축 | 값 | 붙이는 규칙 |
|---|---|---|
| **계절** (4) | `봄` `여름` `가을` `겨울` | 행사는 **개최 시기 기준 1개 이상**. 글·트렌드는 계절색이 뚜렷할 때만. |
| **결** (5) | `축제` `전시` `이야기` `빛깔` `꽃 다루기` | **모든 행에 최소 1개.** |
| **자리** (4) | `서울·수도권` `지방` `해외` `온라인` | **모든 행에 정확히 1개.** |

- `축제` 는 사람들 사이에서 왁자하게 보는 것, `전시` 는 조용히 걸으며 보는 것으로 가른다.
  둘 다인 행사(정원 박람회)는 두 개를 함께 붙인다.
- `빛깔` 은 색이 주인공인 항목(올해의 컬러·팔레트·비주얼 기획)이다.
- `꽃 다루기` 는 손으로 하는 실용 정보다. `이야기` 와 겹치지 않게 한다.
- **온라인**은 물리적으로 갈 곳이 없는 것 전부다(읽을거리 대부분이 여기 온다).

> ⚠ **어휘를 늘리지 마라.** `/stories` 가 꽃말 테마 8칩 + 계열 5칩으로 굴러가는 선례가
> 있다. 칩이 스무 개가 되면 필터가 아니라 벽이 된다. 새 값이 필요하면 **기존 값 하나를
> 지우고 넣는다**는 각오로 판단한다.

### 3-3. `links_to` — 이 읽을거리와 이어지는 **우리 것**

이 칸이 「읽을거리」를 단순 링크 모음이 아니게 만드는 지점이다.

| 형식 | 뜻 | 참조 원본 |
|---|---|---|
| `flower:<id>` | 우리 도감의 그 꽃 | `content/flowers.csv` 의 `id` |
| `color:<색>` | 우리 색 표기 | `content/flowers.csv` 의 `colors` 어휘 |
| `theme:<계열>` | 화면의 빛깔 5종 | `src/components/stories/categories.ts` |

- 색 어휘: `red` `pink` `yellow` `white` `cream` `purple` `orange` `blue` `green`
  `magenta` `coral` `brown` `variegated`
- 계열 라벨 ↔ 코드 키: `숲빛`=forest · `상아빛`=ivory · `금빛`=gold · `와인빛`=wine ·
  `보랏빛`=dusk. **CSV 에는 한글 라벨을 적고**, 코드로 옮길 때 위 표로 매핑한다.
- ⚠ **억지로 잇지 마라. 빈칸이 정답인 경우가 많다.** 색이 실제로 안 맞으면 비운다.
  대조 근거는 `editorial_note` 나 §4 에 남긴다.
- `flower:` 는 반드시 `flowers.csv` 에 실재하는 `id` 여야 한다. 화면 worker 가 이 값으로
  도감에 링크를 걸 것이므로, 없는 id 를 적으면 조용히 깨진 링크가 된다.

### 3-4. 규범 — **보이지 않는 칸에 중요한 사실을 묻지 마라**

> `editorial_note` 는 **화면에 나가지 않는다.** `quotes.pd_basis` · `birth_flowers.editorial_note`
> 와 같은 취급이다. 그러므로 **사용자의 결정을 바꾸는 사실이 거기에만 있으면 없는 것과 같다.**

화면을 만들 사람은 `editorial_note` 를 그리지 않는다. 그걸 전제로 데이터를 짜야 한다.

**옮겨야 하는 것 — 갈지 말지, 누를지 말지를 가르는 사실**

| 사실 | 어디로 |
|---|---|
| 콘텐츠 장벽(로그인·구독·열람 횟수 제한) | **`access`** (`paywall` / `registration`) |
| 행사 입장료·관람료 | **`summary_ko`** — 금액까지 적는다 |
| 일정이 아직 `(예정)` 인 것 | **`summary_ko`** |
| 공식이 월까지만 공지해 날짜가 정확하지 않은 것 | **`summary_ko`** |
| 기간 중 일부 장소가 닫히는 것 | **`summary_ko`** |
| 첫날이 회원 전용이라 일반 관람일이 다른 것 | **`summary_ko`** |
| 우리 다른 데이터와 값이 어긋날 수 있다는 것 | **`summary_ko`** |
| 예약 필수 · 주차 불가 · 우천 취소 | **`summary_ko`** (앞으로 생기면) |

**남겨도 되는 것 — 편집자만 알면 되는 것**: 어느 URL 이 404 인지, 어떤 종을 왜 안 이었는지,
제목 표기를 어떻게 줄였는지, 봇 차단 이력, 우리가 헥스를 안 적은 이유.

#### `access` 를 가르는 기준

`access` 는 **그 링크를 눌렀을 때 글을 읽을 수 있는가**만 말한다. 행사 입장료는 여기가 아니다
— 그건 콘텐츠 장벽이 아니라 **다른 종류의 사실**이라 `summary_ko` 로 간다.

| 값 | 쓰는 때 |
|---|---|
| `open` | 그냥 읽힌다 |
| `paywall` | 구독·결제가 필요하거나 **열람 횟수 제한이 있어 막힐 수 있다** |
| `registration` | 무료지만 가입·로그인이 필요하다 |

> **"열릴 수도, 막힐 수도" 는 `paywall` 이다.** 막혔을 때의 실망이 열렸을 때의 이득보다
> 크기 때문이다. 미리 알리고 열리면 다행인 편이 낫다.
> → 내셔널지오그래픽(`read-natgeo-aalsmeer`) 을 `open` 에서 `paywall` 로 올린 근거다.
> 현재 이 파일의 유일한 비-`open` 항목이다(53 `open` · 1 `paywall`).

## 5. URL 판정과 기각

### 5-1. 판정 방법

**전 50건을 실제로 열어 확인했다.** 검색 결과 스니펫으로 대신하지 않았다.

```
curl -sSL -A "<브라우저 UA>" -H "Accept: text/html,…" -H "Accept-Language: ko-KR,…" \
     --compressed -w "\n@@STATUS:%{http_code}\n@@FINAL:%{url_effective}\n" "<url>"
```

확인한 것: **HTTP 200** · **최종 도착지**(엉뚱한 리디렉션이 없는지) · **`<title>`** ·
**본문 실재**(로딩 셸·로그인 벽·소프트 404 가 아닌지).

### 5-2. 403 은 죽은 링크가 아니다 — 갈라서 기록한다

파트너 페이지가 TLS 문제를 두 갈래로 나눠 적은 것과 같은 자리다.

| 증상 | 뜻 | 처분 |
|---|---|---|
| **404 / DNS 실패 / 인증서 도메인 불일치** | 진짜로 못 간다 | **뺀다** |
| **403 · Cloudflare `Just a moment…`** | 사람 브라우저는 열리는데 자동 요청만 막힌다 | **빼지 않는다.** 표기만 남긴다 |
| **200 인데 빈 껍데기(JS 셸)** | 내용을 검증할 수 없다 | **뺀다** |

싣되 봇 차단이 관찰된 항목 — **주간 점검에서 이것들을 죽은 링크로 오판하지 마라**:

- `kew.org` (2건) — UA 만으로는 간헐 403. 전체 브라우저 헤더를 붙이면 매번 열린다.
- `si.edu/openaccess` — 간헐적으로 `Smithsonian request verification`. 재시도하면 열린다.
- `rhs.org.uk` (4건) — 기본 페처는 막히고 브라우저 UA 로는 정상.

## 6. 만료 항목 거르기 — **화면 worker 가 반드시 읽을 절**

> 이 섹션의 최대 위험은 **지난 행사가 화면에 남는 것**이다. 데이터에 종료일이 있으니
> 거를 수 있다. 거르지 않으면 "10월에 끝난 축제"를 12월에 추천하는 서비스가 된다.

### 6-1. 판정 규칙 (그대로 구현하면 된다)

기준 시각은 **브라우저의 오늘**(`new Date()`)이다. 빌드 시각이 아니다 — 이유는 §7-2.
날짜 비교는 **KST 기준 날짜 문자열**(`YYYY-MM-DD`)끼리 하는 것이 안전하다. `Date` 객체로
비교하면 UTC 자정 경계에서 하루가 밀린다.

| 상태 | 조건 | 화면 처리 |
|---|---|---|
| **끝남** | `ends_at` 이 있고 `ends_at < 오늘` | **숨긴다.** 목록에 넣지 않는다. |
| **열림** | `starts_at <= 오늘 <= ends_at` | 보인다. `지금 열려 있어요` 강조 가능. |
| **아직** | `starts_at > 오늘` | 보인다. `D-n` 또는 `n월 n일부터` 로 알린다. |
| **날짜 없음** | `kind != event` | 만료 판정 대상이 **아니다.** 항상 보인다. |
| **연례 미정** | `kind == event` 인데 날짜가 빈 행 | **지금 이 파일에는 없다.** §6-2 참조. |

```
끝남      = ends_at !== '' && ends_at < todayKST
아직      = starts_at !== '' && starts_at > todayKST
열림      = !끝남 && !아직
```

- **`ends_at` 이 빈 `event` 행을 만들지 마라.** 만료를 판정할 수 없는 행사는 영원히
  목록에 남는다. 그래서 이 파일은 `event` 행에 날짜를 **필수**로 걸었다.
- **경계는 포함이다.** 오늘이 마지막 날인 행사는 아직 갈 수 있다(`<`, `>` 를 쓰고
  `<=`, `>=` 로 뒤집지 않는다).
- **월 단위로만 공지된 행사**는 그 달 말일을 `ends_at` 에 넣고 `editorial_note` 에
  `월 단위 공지` 라고 적어 두었다. 화면에서는 정확한 날짜인 척하지 말고
  `9월까지` 처럼 **달로 말한다**.

### 6-2. 연례 행사인데 다음 회차가 미정일 때

**날짜를 지어내지 않는다.** `starts_at` 이 필수인 이 스키마에서는 그런 행을 만들 수
없으므로, 지금은 **§5-3 「일정 미정 대기 목록」에만 적어 두었다.**

나중에 "해마다 열려요" 카드를 화면에 두고 싶어지면 **컬럼을 하나 더 만들고**(예:
`recurrence`) 날짜 칸을 비운 채로 싣는다. 지금 스키마로 억지로 넣지 마라 —
빈 `ends_at` 은 §6-1 의 판정을 통과해 **영원히 안 사라지는 행**이 된다.

### 6-3. 목록이 텅 비는 날을 대비하라

가을 축제가 전부 끝나는 **11월 말~1월** 에는 `event` 가 거의 다 걸러진다.
그때 화면이 빈 채로 남으면 고장처럼 보인다. 처방 두 가지:

1. **갈래를 섞어 보여 준다.** `article` `guide` `trend` 는 만료가 없다 — 행사가 없는
   달에도 목록은 채워진다. 기본 정렬을 "행사 먼저, 그다음 읽을거리" 로 두면 자연스럽다.
2. **끝난 행사는 조용히 빠지게 한다.** "종료된 행사입니다" 카드를 남기지 마라.
   지난 것을 보여 주려고 만든 섹션이 아니다.

## 7. 배포와 갱신

### 7-1. 지금 — 정적 배포로 문제없이 돈다

`reads.csv` 는 다른 콘텐츠 CSV 와 **같은 길**을 탄다. 새 인프라가 필요 없다.

```
content/reads.csv
  → scripts/build-demo-catalog.mjs   (빌드 때 브라우저용 번들로 굳힌다)
  → next build                       (out/ 한 폴더)
  → Netlify 에 올린다
```

- **서버도, 크롤러도, API 키도 필요 없다.** 링크는 전부 실제 URL 이고, 클릭하면
  사용자의 브라우저가 그 사이트로 갈 뿐이다. 우리 서버가 남의 사이트를 대신
  불러오지 않는다(그 순간 프록시가 되고, 저작권·트래픽 문제가 우리 것이 된다).
- **본배포(서버 액션 있는 쪽)에서도 똑같이 돈다.** 이 섹션에 서버가 필요한 기능이
  없기 때문이다 — 읽기 전용 목록이다.
- 시드 파이프라인에 태우려면 `db/seed/schemas.ts` 의 `SEED_FILE_KEYS` ·
  `SEED_FILE_NAMES` · `SEED_SCHEMAS` 세 곳에 `reads` 를 등록한다.
  **아직 등록하지 않았다** — 스키마 등록은 화면과 함께 오는 다음 단계다.

### 7-2. 정적 배포의 진짜 제약 — 빌드 시점에 "오늘"이 굳는다

이게 유일한 실제 함정이다.

> 빌드 때 `new Date()` 로 거르면, **배포한 날의 오늘**이 HTML 에 박힌다.
> 10월에 배포한 사이트는 12월에도 10월 기준으로 행사를 보여 준다.

**처방: 거르기를 브라우저에서 한다.** 서버가 필요 없는 처방이다.

- 목록 전체를 정적으로 내보내고, **클라이언트에서** `ends_at` 을 오늘과 비교해 숨긴다.
- 서버 렌더 단계에서는 **거르지 않는다**(거기서 거르면 그 판정이 굳는다).
- 첫 페인트에 만료 항목이 잠깐 보였다 사라지는 깜빡임이 싫으면, 목록 컨테이너를
  마운트 이후에 그리거나 만료 판정 전까지 항목을 `hidden` 으로 둔다.
- ⚠ **사용자 기기 시계를 믿는 셈**이라는 걸 알고 있어야 한다. 시계가 틀린 기기에서는
  판정도 틀린다. 이 정도 위험은 감수한다 — 대안은 서버를 세우는 것뿐이고, 잘못
  보이는 최악이 "지난 축제가 하나 남는 것"이라 비용이 맞지 않는다.
- 접근성: 만료로 사라지는 항목 때문에 목록 개수가 바뀐다. 개수를 화면에 적는다면
  **거른 뒤의 수**를 적는다.

### 7-3. 갱신 흐름 — 주간 리서치 루틴에 편입하는 안

**즉시성은 없다.** PR 이 병합되고 재배포돼야 화면이 바뀐다. 이 섹션의 성격상
그것으로 충분하다 — 축제 일정은 분 단위로 바뀌지 않는다.

루틴(월요일 09:17 KST, `research/weekly-*` 브랜치 PR)에 넣을 **지침 초안**:

> **주간 「읽을거리」 점검**
>
> 1. **만료 청소.** `content/reads.csv` 에서 `ends_at < 오늘` 인 `event` 행을 찾아
>    **삭제한다.** 데이터에 남겨 두지 않는다(화면이 거른다 해도 원장이 지저분해진다).
>    지운 항목은 PR 본문에 목록으로 적는다.
> 2. **링크 생존 확인.** 전 행 `source_url` 을 브라우저 UA 로 확인한다(§5-1 방법 그대로).
>    - 404·DNS 실패·도메인 불일치 → **행을 뺀다.** 문구를 고치지 않는다.
>    - 403(봇 차단) → **빼지 않는다.** 죽은 링크와 다르다. PR 본문에 표기만 한다.
> 3. **대기 목록 확인.** §5-3 의 「일정 미정」 행사들의 공식 사이트를 다시 열어,
>    다음 회차 날짜가 올라왔으면 행을 만들어 넣는다. **주최 측 공식 안내에서만**
>    날짜를 가져온다(기사·블로그 재인용 금지).
> 4. **계절 보충.** 다음 6~10주에 열리는 행사가 3건 미만이면 새로 찾는다.
>    `tags` 의 계절 값이 지금 계절과 맞는 항목이 목록에 있어야 한다.
> 5. **§3-4 규범 훑기.** 새로 넣은 행의 `editorial_note` 에 **사용자의 결정을 바꾸는 사실**
>    (입장료·예약 필수·`(예정)` 표기·휴관·열람 횟수 제한 등)이 숨어 있지 않은지 본다.
>    있으면 `summary_ko` 나 `access` 로 올린다. **보이지 않는 칸에 적어 두고 알렸다고 치지 마라.**
>    기존 행도 사정이 바뀌면(예: `(예정)` 이 확정되면) 문장을 함께 고친다.
> 6. **연 1회(12월).** 올해의 컬러 항목을 갱신한다 — 팬톤·WGSN 등이 새 해의 색을
>    발표하는 시기다. 이전 해 항목은 지우지 말고 `editorial_note` 에 연도를 남긴 채
>    둘지, 새 항목으로 갈지 그때 판단한다.
>
> **PR 에 반드시 적을 것**: 추가/삭제한 행 수, 죽은 링크와 그 판정, 새로 확인한
> 행사 날짜와 **그 날짜를 본 공식 URL**.
>
> ⚠ **크롤러를 만들지 마라.** 이 루틴은 사람(또는 사람이 검토하는 에이전트)이
> 링크를 열어 보는 일이다. 그게 §1 의 원칙이다.

### 7-4. 나중 선택지 — 공공데이터 API

붙이면 좋아 보이는 것들이 있다. **판단은 배포 후로 미룬다.** 지금 정할 필요가 없다.

| 후보 | 붙이면 되는 것 | 붙이려면 필요한 것 |
|---|---|---|
| aT 화훼 경매 시세 | "요즘 장미 값" 같은 살아 있는 숫자 | API 키 · 서버리스 함수 · 캐시 |
| 한국관광공사 축제 정보 | 행사 목록 자동 갱신 | API 키 · 서버리스 함수 · **날짜 검증은 여전히 사람 몫** |
| 기상청 개화 시기 | "이번 주 벚꽃" | API 키 · 서버리스 함수 |

**굳이 안 붙여도 되는 이유**: 지금 이 섹션이 약속하는 것은 *잘 고른 읽을거리*이지
*실시간 데이터*가 아니다. 실시간을 약속하는 순간 그 약속을 지킬 의무가 생기고,
API 가 죽는 날 화면이 깨진다. 정적 목록은 그런 방식으로 깨지지 않는다.
그리고 **경매 시세는 소비자 가격이 아니다** — 파트너 페이지가 이미 기록해 둔 함정이라
(`docs/partners-research.md` §2 B-2), 숫자를 화면에 걸면 그 오해를 우리가 만든다.

**붙이기로 한다면 결정해야 하는 것 목록:**

1. 키를 어디에 두는가 — 브라우저에 심는 길은 없다. 서버리스 함수가 필요하고,
   그 순간 **정적 배포가 아니게 된다**(본배포 쪽으로 가야 한다).
2. 캐시 수명 — 경매는 하루 단위인데 함수를 매 요청 부르면 쿼터가 녹는다.
3. API 가 죽었을 때 화면 — 빈칸인가, 마지막 값인가, 블록 자체를 숨기는가.
4. 그 숫자가 무엇인지 **화면에 정직하게 적을 문구**(도매가 ≠ 소비자가).
5. 공공데이터 이용약관의 출처 표기 의무를 어디에 적을 것인가.
